# aiTrade 요구사항

확정된 기능과 범위를 정리한다. 추가 합의가 필요한 내용은 **제안**·**미정**·**보류**로 표시한다.

금융 용어의 뜻과 프로젝트에서 사용하는 기준은 [금융 용어](FINANCIAL_GLOSSARY.md)를 참고한다.

## 1. 프로젝트 방향과 사용 환경

- 작은 기능부터 시작해 필요할 때 기능을 추가한다. 최적화는 실제 문제가 관찰된 뒤 진행하며, 메시지큐·캐시·Redis 등을 처음부터 도입하지 않는다.
- 사용자의 노트북에서 Docker로 실행하고, 집 Wi-Fi에 연결된 기기에서만 접속한다.
- 개인 사용자 1명이 간단한 로그인으로 사용한다. PC와 휴대폰 화면을 지원한다.
- 화면은 다크모드를 기본으로 한다.
- 클라우드 외부 배포 시점은 사용자가 완성도를 판단해 결정한다.
- 기능의 문제·해결 방법·수치 개선·최종 결과를 [성장 기록](GROWTH_LOG.md)에 남긴다.

### 증권사와 대상 자산

| 구분 | 역할 |
|---|---|
| 토스증권 | 주식 매매, 보유종목·주문·거래내역 조회, 필요한 시장 정보 조회 |
| KIS | 필요한 시장 정보 조회만 사용. 실전 계좌이며 KIS를 통한 매매는 하지 않음 |

1차 대상은 **국내 주식·국내 ETF·미국 주식**이다. 해외 ETF는 후속으로 추가한다.

## 2. 1차: 관심종목 관리와 실시간 시세

### 화면

메인 화면의 이름은 **종목**이다. 1차에는 관심종목 목록과 시장별 장 상태를 표시한다. 보유 탭과 개별 종목 상세는 2차에 추가한다.

### 이름 검색과 추가

- 종목 추가를 선택하면 현재 화면 위에 검색 화면이 열린다. 다른 페이지로 이동하지 않는다.
- 이름을 입력하거나 수정할 때마다 해당 입력에 맞는 종목 결과가 표시된다.
- 검색 결과를 선택해 관심종목에 추가한다.
- 추가에 성공하면 성공 여부를 표시하고 검색 화면을 유지해 다른 종목을 계속 검색·추가할 수 있게 한다.
- 검색 결과에 종목명·종목코드/티커·시장을 표시한다. 이미 관심목록에 등록된 종목은 ‘등록됨’으로 표시하고 중복 추가를 막는다.
- 검색 중에는 로딩을 표시하고, 결과가 없으면 ‘검색 결과 없음’을 표시한다. 검색 요청이 실패하면 오류와 재시도 버튼을 표시한다.
- 검색 화면을 닫으면 기존 관심목록의 스크롤 위치와 순서를 유지한다.

첨부한 검색 화면은 입력창과 결과 목록이 기존 화면 위에 뜨는 방식을 참고한다.

### 관심종목 관리

- 등록한 관심종목을 제거할 수 있다.
- 사용자가 목록 순서를 변경할 수 있다. PC와 휴대폰 모두에서 조작할 수 있어야 한다.
- 관심종목과 순서는 노트북 서버에 저장하며, 새로고침·앱 재시작 후에도 유지한다. PC와 휴대폰은 같은 목록을 사용한다.
- 다른 기기에서 변경한 목록은 화면을 열거나 새로고침할 때 반영한다. 열린 화면의 목록을 즉시 동기화하지 않는다. 이 규칙은 목록 변경에만 적용하며 주가의 실시간 갱신은 유지한다.

### 실시간 시세

토스증권을 기본 시세 출처로 사용하고, 토스에서 제공하지 않는 정보만 KIS로 보완한다. 같은 종목의 현재가와 등락 기준 가격은 같은 출처를 사용한다. 1차에는 장애 시 증권사를 자동 전환하지 않는다.

관심종목마다 다음을 표시한다.

| 항목 | 의미 |
|---|---|
| 현재가 | 해당 종목의 최신 제공 가격과 통화 |
| 등락 금액 | 기준 가격에서 얼마나 올랐거나 내렸는지, 원·달러 등 해당 통화로 표시 |
| 등락률 | 같은 기준 가격 대비 변화율을 퍼센트로 표시 |
| 등락 방향 | 국내·미국 모두 상승 빨강·하락 파랑·보합 회색으로 표시. 등락 금액과 등락률에 상승은 `+`, 하락은 `−` 부호 표시 |

등락 금액과 등락률은 각 시장의 **직전 거래일 정규장 종가**를 기준으로 계산한다. 같은 거래일의 정규장·시간외 모두 이 기준을 유지하며, 다음 거래일이 시작되면 기준 가격을 갱신한다. 거래일 구분은 해당 시장의 장 캘린더를 따르며 한국시간 자정에 임의로 기준을 바꾸지 않는다.

예를 들어 직전 거래일 종가가 100, 오늘 정규장 종가가 110, 오늘 시간외 가격이 108이면 시간외에도 전일 대비 `+8`, `+8%`로 표시한다.

- 시세 연결이 끊기면 마지막 수신 가격과 등락을 유지하고, ‘연결 끊김’과 마지막 수신 시각을 표시한다.
- 자동 재연결을 시도하며, 재연결 후 해당 종목의 최신 시세를 받은 뒤 정상 표시로 돌아간다. 연결만 복구된 상태에서 기존 가격을 최신 가격으로 표시하지 않는다.
- 실시간 스트리밍을 제공하지 않는 종목은 조회 API에서 가격을 제공하는 경우 주기 조회로 표시한다. 화면에 ‘주기 조회’와 갱신 주기를 표시하고, 원천 데이터가 지연 시세이면 지연 여부도 표시한다.
- 실제 조회 주기는 API 지원과 호출 한도를 확인한 뒤 정한다.

### 장 상태와 시간

- 국내와 미국의 장 상태를 각각 확인할 수 있어야 한다.
- 1차부터 API가 제공하는 **정규장·시간외 등 모든 세션**의 장 상태와 시세를 표시한다. 실제 지원 세션은 연동 시 확인한다.
- 현재 어떤 장이 진행 중인지, 그 장의 시작·종료 일시와 시간대를 표시한다.
- 시간은 **한국시간(KST)**을 기본으로 한다. 자정을 넘는 세션은 날짜도 표시해 시작·종료를 구분한다.
- 거래시간 외·휴장·장 정보 확인 실패를 구분해 표시한다. 거래시간 외·휴장에는 다음 세션 시작 일시를 확인할 수 있으면 함께 표시한다. 장 정보 확인 실패에는 재시도 버튼을 표시하며, 실패를 휴장이나 거래시간 외로 표시하지 않는다.

## 3. 2차: 보유종목과 수동매매

### 목록과 상세 화면

- 종목 화면에 **관심 / 보유** 탭을 추가한다.
- 관심 탭은 사용자가 등록한 종목, 보유 탭은 토스 계좌에서 실제 보유한 종목을 보여준다.
- 종목을 선택하면 PC에서는 **우측 상세 패널**, 휴대폰에서는 **전체 너비 상세 화면**을 연다.
- PC에서는 상세 패널을 열어 둔 채 목록의 다른 종목을 선택할 수 있다.

관심 등록 여부와 보유 여부는 독립적이다. 보유한 종목이 관심 목록에 없을 수 있으며, 관심에서 제거해도 보유종목은 유지한다.

### 보유 정보와 주문 입력

종목 상세에서 자신의 보유 정보를 확인하고 매수·매도할 수 있어야 한다. 처음에는 다음 정보를 표시하며, 차트·호가창은 후속으로 추가한다.

| 영역 | 표시 정보 |
|---|---|
| 종목 | 이름·코드/티커·시장·현재가·통화·등락 금액·등락률(1차와 같은 기준) |
| 내 보유 | 보유수량·평균매입가·비용 반영 전 평가손익·세금·수수료·비용 합계·비용 반영 후 순평가손익·수익률 |
| 주문 입력 | 매수/매도 구분·가격·수량·예상 주문금액 |

2차의 비용 반영 전·후 평가손익과 세금·수수료는 토스 API 제공 값을 사용한다. 수익률은 토스 API의 비용 반영 후 값을 사용하며, 평가손익과 수익률을 앱에서 별도로 재계산하지 않는다. 국내는 원화, 미국은 달러로 표시하고 비용 반영 전·후를 구분한다. 예상 비용과 확인되지 않은 값은 아래 손익 표시 규칙에 따른다.

사용자가 가격과 수량을 정해 토스증권으로 지정가 매수·매도 주문을 제출한다. 2차의 첫 버전은 지정가 주문만 지원하며, 시장가 주문은 후속으로 추가한다.

- 2차부터 정규장과 시간외를 포함하되, 토스 API에서 지정가 주문 지원이 확인된 세션·종목에서만 주문을 제공한다. 시세 제공이나 장 운영 시간 조회만으로 주문 가능 여부를 판단하지 않는다.
- 각 세션의 접수 가능 시간·미체결 주문 만료·다음 세션으로의 이월 규칙을 확인한 뒤 활성화한다. 미확인 세션에서는 주문 제출을 비활성화하고 ‘주문 지원 확인 전’으로 표시한다.
- 토스 API가 지원하지 않는 국내 장전·장후 시간외종가 주문은 제외한다. 미국 시간외 세션과 국내 시간외 단일가 주문의 지원 여부는 추가 확인이 필요하다.
- 2차 첫 버전에 미체결 잔여수량 취소와 토스 API가 허용하는 가격·수량 정정을 포함한다. 이미 체결된 수량은 정정·취소 대상에서 제외한다. 정정·취소 전에 변경 내용을 확인하며, 해당 종목·세션·주문에서 지원하지 않는 정정 항목은 입력하거나 제출할 수 없게 한다.

### 주문 입력 중 종목 전환

- 주문 가격이나 수량을 입력한 상태에서 다른 종목을 선택하면 입력 중인 주문을 지우고 이동할지 확인한다. @@@@@@
- 동의하면 기존 입력을 지우고 새 종목으로 이동하며, 새 종목의 주문 입력을 초기화한다. 취소하면 기존 종목과 입력을 유지한다.
- 가격·수량을 아직 입력하지 않았다면 확인 없이 바로 이동한다. 종목별 주문 초안을 임시 보관하거나 복원하지 않는다.
- 종목 전환과 입력 초기화는 이미 제출한 주문을 정정하거나 취소하지 않는다.

### 주문 제출과 접수 확인

- 제출 전에 종목·매수/매도·가격·수량·예상 주문금액을 확인하고, 사용자가 확인한 뒤 주문을 제출한다.
- 주문 전송 중에는 동일 주문의 중복 제출을 막는다.
- 응답이 끊기는 등 접수 결과가 불명확하면 ‘접수 확인 중’을 표시하고 주문 조회로 접수 여부를 확인한다. 접수 여부가 확인되기 전에는 같은 주문을 자동으로 다시 보내지 않는다.

### 주문과 거래내역

주문 정보와 거래내역을 확인하는 화면을 제공한다. 2차 첫 버전은 주문 단위로 표시하며, 개별 체결 이벤트 수집·표시는 포함하지 않는다.

| 구분 | 표시 정보 |
|---|---|
| 주문 | 종목·매수/매도·주문가격·주문수량·체결수량·잔여수량·상태·주문시각 |
| 거래내역 | 종목·매수/매도·평균 체결가격·총 체결수량·마지막 체결시각·통화 |

주문 접수와 체결은 구분한다. 하나의 주문이 여러 번 나누어 체결되어도 거래내역에는 주문 1건을 1행으로 표시한다. 평균 체결가격과 총 체결수량은 그 주문에서 실제 체결된 수량만 대상으로 하며, 마지막 체결시각은 가장 최근 체결의 시각이다. 미체결 수량은 거래내역에 포함하지 않고, 부분체결 후 잔여수량을 취소한 주문도 실제 체결 결과를 유지해 표시한다.

- 거래내역은 기본으로 최근 1개월을 표시한다. 시작일·종료일을 선택하면 토스 API가 제공하는 범위에서 과거 내역을 조회한다.
- 내역이 많으면 한 번에 모두 불러오지 않고 ‘더 보기’로 다음 내역을 이어서 불러온다.

### 알림

- 2차 첫 버전은 앱이 열려 있을 때 앱 내부에서 주문 접수·부분체결·전체체결·거부를 구분해 알린다.
- 앱 화면을 닫으면 알림을 전달하지 않는다. 다시 열면 최신 주문·체결 상태를 조회해 표시한다.
- 화면을 닫아도 PC·휴대폰에서 받을 수 있는 외부 알림은 후속으로 추가한다.

## 4. 3차: AI 자동매매

### 초기 목표

- AI가 토스증권·KIS에서 필요한 정보를 가져와 종목과 매매 시점을 판단하고, 토스증권을 통해 실제 거래한다.
- 관심종목 밖에서도 투자 후보를 선택한다. 관심 목록은 사용자가 보는 목록이며 AI의 전체 투자 범위가 아니다.
- 첫 전략의 투자 대상은 국내 주식·국내 ETF다. 미국 주식 자동매매는 후속으로 추가한다. 이 범위는 자동매매에만 적용하며, 1차 시세와 2차 수동매매의 미국 주식 범위는 유지한다.
- 3차 첫 버전부터 성향이 다른 여러 **AI 투자자**를 추가하고 개별 운영할 수 있게 한다. 각 투자자는 자신의 운용금액으로 종목과 매매 시점을 결정한다. 초기 운영은 중기 투자자 1명·전략 1개로 시작하고, 검증하며 다른 성향의 투자자를 추가한다. 전략 간 피드백은 후속으로 구현한다.
- AI가 서버의 조회 도구를 사용해 투자 범위 안에서 종목을 직접 탐색하고, 필요한 종목 데이터를 요청해 투자 후보를 선택한다. 서버가 미리 추린 고정 후보 목록에 한정하지 않는다. 탐색에 사용한 조회와 후보 선택 근거를 기록하며, 현재 보유종목은 탐색 결과와 관계없이 판단에 포함한다. 제공할 탐색 도구와 탐색 종료 조건은 **보류**하고 후속 논의에서 정한다.
- AI가 종목·매수/매도/관망·주문가격·주문수량·판단 근거를 결정한다. 관망에는 주문을 제출하지 않는다. 서버는 거래 가능 여부와 해당 AI 투자자의 사용 가능한 자금·보유수량을 검사한 뒤 토스증권으로 주문한다. 조회 도구는 주문 실행 권한을 갖지 않으며, 검사를 통과하지 못한 판단은 주문하지 않는다.
- 판단에 사용하는 정보와 근거는 최소로 시작한다. 첫 전략의 구체적인 판단 기준·지표는 미정이다.
- 첫 전략에는 AI가 탐색한 종목의 현재가·최근 일봉 가격/거래량, 해당 AI 투자자의 보유·미체결 주문·운용금액을 제공한다. 일봉 조회 기간과 AI의 후보 선택 기준은 미정이다.
- 이후 각종 보조지표·기업 정보·뉴스·공시·재무정보 등을 수집해 판단 입력에 포함한다. 초기 입력과 추가한 정보를 구분해 기록하여 정보 추가 전후의 판단과 결과를 비교할 수 있게 한다.
- 판단 근거와 실제 거래 결과를 남겨 어떤 판단이 어떤 결과로 이어졌는지 확인할 수 있어야 한다.
- 탐색 도구·종료 조건·AI의 후보 선택 기준과 투자자별 실제 운용금액은 실제 자동매매를 시작하기 전에 정한다.

### AI 투자자별 자금과 기록

- AI 투자자는 이름·투자 유형·최초 배정금으로 생성한다. 투자 유형은 **초단타·중기·장기 중 하나**를 선택한다. 매매 스타일·선호 지표 등 다른 성향 항목이나 자유 설명 입력은 요구하지 않는다.
- 투자 유형별 전략을 미리 정의하고 실제 AI 판단에 반영한다. 선택한 유형과 적용 전략을 기록해 어떤 설정으로 어떤 판단·거래·성과가 나왔는지 연결한다. 유형별 판단 기준과 필요한 데이터는 전략 설계 때 정하도록 **보류**한다.
- 초단타는 수초~수분 단위로 매매하고, 매수한 종목을 같은 거래일 안에 청산해 다음 거래일까지 보유하지 않는 유형이다. 당일 청산 시점과 미체결·거래 중단 등으로 청산하지 못한 경우의 처리 방식은 초단타 유형을 추가할 때 정하도록 **보류**한다.
- 중기는 수일~수주, 장기는 수개월 이상을 기본 보유기간으로 하는 유형이다. 보유기간은 유형별 전략 기준이며 사용자가 별도로 입력하는 설정은 아니다.
- 사용자가 AI 투자자마다 원화 최초 배정금을 지정한다. AI는 배정금을 임의로 변경하거나 다른 투자자의 자금을 사용할 수 없다.
- 초기 설정은 운용금액만 지정한다. 1회 주문금액·종목별 투입금액 상한과 손실률에 따른 자동 중지 기준은 두지 않는다. 손실 제한 없이도 AI는 배정받은 자산만 사용할 수 있다.
- AI 투자자별로 관리 종목·보유수량·금액·투자이익·주문·거래내역을 구분해 기록한다. 같은 종목을 여러 AI가 보유할 때도 각 투자자의 수량과 거래 귀속을 구분해야 한다.
- 운용금액은 최초 배정금이며 고정 매입원금 상한으로 사용하지 않는다. 거래 결과와 비용에 따라 해당 투자자의 자산이 늘거나 줄고, 수익은 재투자할 수 있다. 최초 배정금과 현재 현금·보유자산은 구분해 표시한다. 수익 재투자는 최초 배정금 설정을 변경하는 동작이 아니다.
- 실제 주문은 토스 실계좌 하나를 사용한다. 앱 내부 장부에서 개인과 각 AI 투자자의 현금·보유수량·주문·거래·성과를 구분하며, AI별 실제 증권계좌를 개설하거나 연결하지 않는다.
- 주문 제출 전에 매수에 필요한 현금 또는 매도할 수량을 해당 투자 주체의 보유분에서 묶어 둔다. 묶인 현금·수량은 다른 주문이나 자금 배정·회수에 중복 사용하지 못하며, 개인 수동 주문·AI 자동 주문·AI 보유분의 수동 매도에 같은 규칙을 적용한다.
- 체결된 부분은 실제 거래 결과대로 현금·보유수량에 반영하고, 미체결 부분은 계속 묶어 둔다. 전량 체결·취소·거절 등으로 주문이 종료된 것을 확인하면 남은 예약 금액·수량을 해당 투자 주체가 다시 사용할 수 있게 한다. 주문 상태가 불명확하거나 취소 확인 중이면 종료를 확인할 때까지 묶인 상태를 유지한다.
- 같은 계좌의 현금이나 보유수량을 여러 투자자에게 중복 배정하거나 주문에 중복 사용하지 않도록 관리한다. 자동매매 재개 전, 체결 반영 후, 자금 배정·회수 후에 개인과 모든 AI의 현금·보유수량 장부 합계를 실제 계좌와 대조한다.
- 앱 장부와 실제 계좌가 불일치하면 모든 AI 투자자의 신규 자동 주문을 차단하고 사용자에게 불일치를 표시한다. 이미 시작한 AI 판단의 결과도 새 주문으로 제출하지 않는다. 원인을 확인·해소하고 장부와 실제 계좌가 일치하는지 다시 확인한 뒤 사용자가 재개한다. 불일치로 인한 차단 중에는 기존 주문을 유지하고 상태 확인을 계속한다. 사용자가 AI 중지를 요청하면 아래 주문 취소 규칙을 적용한다.
- AI에 현금을 배정하면 개인 장부의 현금에서 해당 금액을 차감하고 해당 AI의 현금으로 기록한다. 배정 자체는 실제 계좌의 총현금을 바꾸지 않으며 투자수익으로 계산하지 않는다. 기존 개인 보유종목은 개인에 귀속한다.
- 사용자가 추가 자금 배정·회수를 요청하면 해당 AI의 중지 처리가 완료된 뒤 주문과 현금을 확인하고, 개인과 해당 AI 사이에서 사용 가능한 현금만 이동한다. 주문에 묶이지 않은 것으로 확인된 현금만 이동할 수 있으며, 이동 가능한 현금을 넘는 요청은 실행하지 않는다. 회수를 위해 보유종목을 자동 매도하지 않는다.
- 추가 배정은 개인 현금을 차감해 해당 AI에 더하고, 회수는 해당 AI 현금을 차감해 개인에게 돌려준다. 최초 배정금은 유지하고 추가 배정·회수를 별도로 기록한다. 자금 이동은 투자수익·손실로 계산하지 않는다.
- 초기 운용에서는 실계좌 입금 후 서버가 실행 중인 상태에서 앱으로 해당 입금액을 AI 최초·추가 자금으로 바로 배정한다. 앱은 사용자가 입력한 입금·배정 금액을 전체에는 외부 자금 유입, 개인과 해당 AI 사이에는 배정으로 같은 시점에 기록한다. AI TWR은 배정 직후부터 계산한다. 별도의 실계좌 입출금 자동 감지와 입출금 기록 화면은 초기 범위에 포함하지 않는다.
- 개인·각 AI의 장부에서 비용 반영 전 매입원가는 투자 주체·종목별 **이동평균**으로 계산한다. 매수 체결 시 평균매입가는 `(현재 보유분의 매입원가 + 추가 매수 체결금액) / (현재 보유수량 + 추가 체결수량)`으로 갱신한다. 세금·수수료는 이 원가에 포함하지 않고 별도로 관리한다.
- 매도 체결 시 원가는 `해당 주체의 평균매입가 × 체결수량`으로 계산하고, 매도 체결금액과의 차이를 비용 반영 전 실현손익으로 기록한다. 남은 보유분의 평균매입가는 유지한다. 전량 매도하면 보유수량과 남은 매입원가는 0이 되며, 다음 매수부터 새 평균매입가를 계산한다. 미체결 주문은 평균매입가를 변경하지 않는다.
- 실제 매수 세금·수수료는 투자 주체·종목별로 남은 보유분에 귀속한다. 추가 매수 시 해당 보유분의 미배분 매수 비용에 새 매수 비용을 더한다. 일부 매도 시 세금·수수료 각각에 대해 `매도 직전 미배분 매수 비용 × 매도 체결수량 / 매도 직전 보유수량`을 실현손익 비용으로 배분하고, 나머지는 남은 보유분의 평가손익 비용으로 유지한다. 전량 매도 시 남은 매수 비용을 모두 실현손익에 배분한다.
- 실현 순손익은 비용 반영 전 실현손익에서 배분된 매수 비용과 실제 매도 체결의 세금·수수료를 차감한 금액이다. 보유분의 순평가손익에는 남은 매수 비용과 별도 표시한 예상 매도 비용을 반영한다. 비용 배분 자체로 현금을 다시 차감하지 않는다.
- 보유분의 예상 매도 비용은 **현재가로 남은 보유수량 전부를 매도한다고 가정**해 산정하고, 예상 세금·수수료·비용 합계를 순평가손익에 반영한다. 예상 비용은 현금에서 실제 차감하지 않는다. 적용 수수료·세금 정보의 출처와 구체적인 산식은 API 확인 후 정한다.
- 개인·전체·개별 AI 화면의 대표 수익률은 **시간가중수익률(TWR)**로 계산한다. 각 화면의 계산 범위에 들어오거나 나가는 자금 이동 직전과 직후의 자산 평가 기록을 남기고, 구간별 수익률을 복리로 연결한다. 자금 이동 금액 자체는 수익·손실로 계산하지 않는다. AI의 성과 측정은 최초 자금 배정부터 시작한다.
- 개인 TWR에서는 개인과 AI 사이의 배정·회수 및 개인 귀속 자금의 계좌 입금·출금을 자금 이동으로 처리한다. 각 AI의 TWR에서는 해당 AI의 배정·회수를 자금 이동으로 처리한다. 전체 TWR에서는 개인과 AI 사이의 이동은 내부 이동이며, 실제 계좌 입금·출금만 외부 자금 이동으로 처리한다.
- TWR의 자산 평가액은 **해당 화면 범위의 현금 + 보유종목의 현재가 평가금액**으로 계산한다. 전체는 개인과 모든 AI의 자산을 합해 직접 계산하며, 개인·AI 수익률을 더하거나 단순 평균하지 않는다. 주문에 묶인 현금·수량도 자산에 포함하되 중복 합산하지 않는다. 실제 발생한 거래 세금·수수료는 현금에 반영하고, 손익 계산을 위한 매수 비용 배분 때 다시 차감하지 않는다.
- 개인·전체·개별 AI의 대표 자산과 TWR은 **원화 기준**으로 계산한다. 달러 현금과 달러 표시 보유종목 평가금액을 각 평가 시점의 적용 환율로 원화 환산해 합산한다. 환율 변화도 원화 기준 TWR에 반영하며, 평가 기록마다 적용 환율·환율 기준 시각·평가 시각을 남긴다. 이 환산은 표시·성과 계산이며 실제 환전을 실행하지 않는다. 환율 출처와 갱신·지연 여부 확인 방법은 API 확인 후 정한다.
- TWR에는 예상 매도 비용을 차감하지 않는다. 예상 매도 비용은 기존 순평가손익에 반영해 별도로 확인할 수 있게 한다. 2차 실제 계좌의 토스 제공 평가손익을 투자 주체별 손익에 그대로 적용할 수 있다고 가정하지 않는다.
- 개인·전체·개별 AI 각각의 계산 범위에서 실제 자산이 0이 되면 해당 운용기간을 종료하고 수익률을 보존한다. 전액 회수는 자금 이동으로 처리해 회수 자체를 손실로 계산하지 않으며, 투자 손실로 자산이 0이 되면 해당 기간의 손실을 유지한다. 사용 가능한 현금만 0이거나 평가 정보를 확인할 수 없는 경우는 자산 0으로 판단하지 않는다.
- 자산이 0인 동안에는 TWR을 계산하지 않고, 다시 자금이 들어오면 새 운용기간의 TWR 계산을 시작한다. 이전 기간과 새 기간의 수익률은 연결하지 않고 기간별로 구분한다. 과거 거래내역·누적 실현손익·AI 최초 배정금 기록은 초기화하지 않는다. AI 중지·재개만으로 운용기간을 나누지 않는다.
- 개인·전체·개별 AI의 자산·TWR 평가 기록은 **한국시간 매일 00:00과 각 계산 범위의 자금 이동 직전·직후**에 저장한다. 일일 평가는 모든 화면 범위에 같은 기준 시각을 적용한다. 자정 기준 자산 평가이며 시장별 종가 기록과 구분하고, 종목의 전일 대비 등락 계산 기준은 변경하지 않는다. 초기에는 일정 간격의 장중 평가 기록을 추가로 저장하지 않는다. 주문·체결·AI 판단 기록은 발생할 때마다 별도로 남긴다.
- 서버 미실행 등으로 일일 평가를 남기지 못한 날짜는 **‘기록 없음’**으로 표시한다. 이전 평가값이나 재시작 시점의 값을 누락 날짜에 채우지 않으며, 초기에는 과거 평가 기록을 복원하지 않는다. 재시작 후 계좌·주문·시세를 확인해 현재 평가를 실제 평가 시각으로 별도 기록하고, 다음 정기 평가는 한국시간 00:00에 진행한다. 이 평가 기록으로 자동매매를 재개하지 않는다.

### 투자 현황 화면

- 투자 현황은 **전체·개인·개별 AI**로 구분한다. 전체는 개인과 모든 AI를 포함하며, AI만 합산하는 별도 화면은 제공하지 않는다.
- 전체 화면에는 개인과 모든 AI의 현금·보유종목·손익·주문·거래내역을 함께 표시한다. 합산 현황과 개인·각 AI별 내역을 확인할 수 있어야 한다. 대표 자산과 TWR은 원화 기준으로 표시하고, 현금 잔액은 통화별로 구분하며 종목 가격·거래금액은 원래 통화로 표시한다.
- 전체 보유목록에서는 같은 종목의 총 보유수량과 개인·각 AI별 보유수량을 확인할 수 있어야 한다. 전체 주문·거래내역에는 각 항목의 투자 주체를 ‘개인’ 또는 AI 이름으로 표시한다.
- 개인 현황에는 AI에 배정한 자금을 제외한 개인 귀속 현금·보유종목·손익·주문·거래내역만 표시한다. 개인 자금으로 한 매매는 개인에, AI 자금으로 한 매매는 해당 AI에 귀속한다.
- 개별 AI 현황에는 해당 투자자의 투자 유형·최초 배정금·현재 현금·관리 종목·보유·손익·TWR·현재 낙폭·최대 낙폭·주문·거래내역을 표시한다. 현재·최대 낙폭은 저장된 성과 평가 기록의 TWR 흐름으로 계산하므로 기록 사이의 장중 저점은 포함하지 않는다.
- 개인과 개별 AI 현황은 동일한 화면 구조를 사용한다. 선택한 투자 주체의 현금·보유종목·손익·주문·거래내역을 표시하며, 화면에 현재 선택된 개인 또는 AI 투자자를 명확히 표시한다.
- 개인·개별 AI 화면에서 손익 금액은 **실현손익·평가손익·총손익**으로 구분해 표시한다. 실현손익은 실제 매도 체결로 확정된 손익, 평가손익은 현재 보유분의 평가에 따른 손익이며, 총손익 금액은 두 금액의 합이다. 미체결 매도 주문은 실현손익에 포함하지 않는다.
- 종목 상세와 전체·개인·개별 AI 현황의 손익에는 **비용 반영 전 손익·세금·수수료·비용 합계·비용 반영 후 순손익**을 함께 표시한다. 비용 합계는 세금과 수수료의 합이며, 실현손익·평가손익·총손익 각각에서 비용 반영 전·후를 구분한다.
- 실제 체결에 대해 확인된 비용과 보유분 평가에 사용한 예상 비용을 구분하고, 예상 금액에는 ‘예상’을 표시한다. 필요한 비용을 확인하지 못하면 해당 비용과 이를 계산에 필요로 하는 순손익에 ‘확인 불가’를 표시한다. API 계약상 비용이 없는 경우만 0으로 처리한다. 같은 비용을 실현손익과 평가손익에 중복 반영하지 않는다.
- 개인의 실현손익은 앱에서 개인 거래 기록을 관리하기 시작한 시점부터 누적한다. 과거 거래 손익 이관은 초기 범위에 포함하지 않는다. 개인의 평가손익은 현재 보유분을 기준으로 표시한다.
- AI의 실현손익은 최초 자금 배정 시점부터 누적하고, 평가손익은 현재 보유분을 기준으로 표시한다. 중지·재개해도 누적 기록을 초기화하지 않는다. 추가 자금 배정·회수 금액은 손익 집계에서 제외한다.
- 전체 보유목록에서 매도를 누르면 해당 종목을 보유한 개인·AI의 이름과 보유수량을 표시하고, 매도할 투자 주체 하나를 선택하게 한다. 개인을 선택하면 개인 매도 입력·주문 확인 절차로, AI를 선택하면 아래 AI 중지 확인·수동 매도 절차로 이어진다. 선택한 주체의 보유분만 매도 대상으로 한다.
- AI 보유목록의 각 종목에 매도 버튼을 제공한다. 해당 AI를 중지하고 모든 자동 주문의 종료를 확인한 뒤에만 수동 매도를 허용한다. 해당 AI의 보유분만 매도 대상으로 하며, 실제 체결 결과를 그 AI의 보유수량·현금·손익·거래내역에 반영하고 ‘사용자 수동 매도’로 표시한다. 미체결 수량은 보유수량에서 차감하지 않는다.
- AI가 실행 중일 때 매도 버튼을 누르면 ‘AI를 중지하고 미체결 주문을 취소한 뒤 매도하시겠어요?’를 표시한다. 동의하면 해당 AI의 중지 절차를 실행하고, 중지 완료 후 매도 입력 화면을 연다. 이미 중지 완료 상태이면 바로 매도 입력 화면을 연다. 매도는 가격·수량 입력과 주문 확인 후 제출하며, 매도 절차를 끝내거나 중간에 닫아도 AI는 중지 상태를 유지한다.

### 판단 실행 시점

- 초기 중기 AI도 하루에 여러 번 후보·보유종목·주문 상태를 확인하고 판단한다. 구체적인 시간대와 간격은 매일·매월·특정 시기에 반복되는 시장 패턴을 전략에 어떻게 반영할지와 함께 정해야 하므로 **보류**한다.
- 정해진 조건이 발생하면 다음 정기 판단을 기다리지 않고 추가 판단을 요청한다. 초기 조건의 종류·기준값과 재판단 범위도 투자 전략과 함께 정하도록 **보류**한다.
- 정기 판단과 조건 판단이 겹치면 하나로 묶고, AI 판단은 동시에 여러 개 실행하지 않는다.
- 같은 조건이 계속 유지된다는 이유로 판단을 반복하지 않도록 재실행 대기시간과 조건 재발생 기준을 둔다. 구체적인 시간과 기준은 투자 전략과 함께 정하도록 **보류**한다.
- 조건 발생은 AI 재판단 요청이며 곧바로 주문을 실행하는 의미가 아니다. 주문에는 거래 가능 여부와 해당 AI 투자자의 자금·보유수량 검사를 동일하게 적용한다.
- 초기 조건 감시와 판단 실행은 서버 안에서 처리한다. 메시지큐는 실제 필요가 관찰된 뒤 도입한다.

### 수동 주문과 자동 주문

- 자동 주문은 AI 투자자별로 순서대로 제출하고, 각 주문의 접수 결과를 처리한 뒤 해당 AI의 다음 주문을 제출한다. 서로 다른 AI는 병렬 제출할 수 있다. 체결 상태는 주문별로 별도 확인하며, 병렬 제출에서도 투자자별 현금·수량 예약과 실제 계좌의 사용 가능 금액·수량 검증을 적용한다. 판단 실행의 동시성은 위 판단 규칙을 유지한다.
- AI가 매도할 수 있는 수량은 해당 AI의 자동매매로 매수한 수량 중 아직 보유 중인 수량으로 한정한다. 개인과 각 AI의 보유수량을 구분해 기록하고, 주문 검증 시 해당 AI의 보유수량과 실제 계좌의 매도 가능 수량을 확인한다. 어느 쪽도 초과하는 자동 매도는 제출하지 않는다.
- 수동 매도는 개인 또는 특정 AI를 선택한 상태에서 해당 투자 주체의 보유분 안에서만 가능하다. 개인 화면에서는 개인 보유분만, AI 화면에서는 중지 완료된 해당 AI 보유분만 매도한다. 선택한 투자 주체의 보유수량을 초과하는 주문은 제출하지 않는다. 예를 들어 개인 8주·AI 5주를 보유하면 개인 화면에서는 최대 8주만 매도할 수 있다.
- 실제 체결수량만 선택한 투자 주체의 보유수량에서 차감하고, 현금·손익·거래내역도 해당 주체에 반영한다. 미체결 수량은 보유수량에서 차감하지 않는다. 이후 AI는 자신의 갱신된 보유수량으로 판단한다.
- 같은 종목에 미체결 또는 접수 확인 중인 수동 주문이 있으면 새 자동 주문을 제출하지 않는다. 매수·매도 방향이 같아도 이 제한을 적용한다.
- 수동 주문이 종료되면 최신 보유·주문 상태를 반영한 새 판단을 거쳐 자동 주문 여부를 결정한다. 제한 중 나온 판단을 그대로 실행하지 않는다.
- AI는 수동 주문을 정정하거나 취소하지 않는다.

### 자동매매 중지와 재개

- 각 AI 투자자에 별도 중지 버튼을 제공한다. 중지 버튼을 누르면 ‘{AI 이름}의 자동매매를 중지할까요? 이 AI의 미체결 자동 주문은 취소됩니다. 보유종목은 그대로 유지됩니다.’를 표시하고 ‘돌아가기’·‘중지 및 주문 취소’ 버튼을 제공한다. 동의하면 중지 절차를 시작하고, 돌아가거나 확인창을 닫으면 현재 실행 상태와 주문을 유지한다.
- 중지 버튼 또는 수동 매도 전 확인을 통해 사용자가 중지하면 해당 AI의 새로운 판단과 자동 주문 제출을 즉시 중단하고, 이미 제출한 자동 주문의 미체결 잔여수량에 취소를 요청한다. 중지 전에 시작한 판단이 완료되어도 그 결과로 새 주문을 제출하지 않는다. 취소 대상은 해당 AI의 자동 주문으로 한정한다.
- 취소 요청 후에도 주문 상태를 조회해 종료 여부를 확인한다. 접수 확인 중인 주문은 접수 여부를 확인한 뒤 미체결 잔여수량을 취소한다. 취소 중 체결된 수량은 실제 체결 결과대로 보유·현금·거래내역에 반영한다.
- 모든 자동 주문의 종료와 최신 보유수량이 확인되면 ‘중지 완료’로 표시한다. 취소 실패·미체결 주문·확인되지 않은 주문이 남아 있으면 ‘중지 처리 중’으로 표시하고 원인과 재확인·취소 재시도 수단을 제공한다. 해당 AI 보유분의 수동 매도와 자동매매 재개는 중지 완료 후에만 허용한다. 개인 수동매매와 다른 AI 투자자의 운영은 해당 AI의 중지로 제한하지 않는다.
- 사용자가 재개하면 최신 시세·보유·미체결 주문·해당 AI의 사용 가능한 현금과 수량을 다시 확인하고, 개인과 모든 AI의 장부 합계를 실제 계좌와 대조한다. 확인이 끝나고 장부와 계좌가 일치하면 즉시 새 판단을 실행한다. 필요한 최신 상태를 확인하지 못하거나 장부가 불일치하면 새 자동 주문을 제출하지 않는다.
- 중지 전에 나온 판단을 재사용하거나 중지 중 놓친 정기·조건 판단을 몰아서 실행하지 않는다. 새 판단 이후에는 정기 판단과 조건 판단을 다시 수행한다.
- 노트북이나 Docker 서버가 재시작되면 이전 실행 상태와 관계없이 자동매매를 중지 상태로 시작한다. 기존 주문의 상태는 다시 조회하며, 사용자가 재개해야 새 판단과 자동 주문 제출을 시작한다.

### 후속 검토: Codex 활용

LLM API에만 의존하지 않고 월 구독 Codex를 활용하는 방법을 검토한다. 증권사에서 얻지 못하는 정보가 필요하면 앱이 요청을 남기고, 맥북의 Codex가 조사한 결과를 앱에 전달해 판단에 활용하는 흐름을 원한다. 연결 방식과 처리 시점은 미정이며, 메시지큐·Kafka 사용을 필수로 정하지 않는다.

### 후속 검토: AI 투자자 간 피드백과 학습

- 서로 다른 성향·지표·장기/단기 전략을 가진 AI가 개별 투자자처럼 투자한다.
- 각 전략의 거래와 성과를 구분해 장점·약점을 관찰한다.
- 결과를 회고하고 서로 의견을 주고받아 전략 보완안을 만든다.
- 변경 전후의 성과를 비교해 보완이 실제로 도움이 되었는지 확인한다.
- 필요하면 ML/DL 모델을 별도로 학습·개선해 투자 판단에 활용한다.

투자자별 현황 관리와 별개로, 전략 간 피드백과 ML/DL 학습은 후속 고도화 방향이다.
