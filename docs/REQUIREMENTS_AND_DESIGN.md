# aiTrade 요구사항

확정된 기능과 범위를 정리한다. 추가 합의가 필요한 내용은 **제안**·**미정**·**보류**로 표시한다.

금융 용어의 뜻과 프로젝트에서 사용하는 기준은 [금융 용어](FINANCIAL_GLOSSARY.md)를 참고한다.

전체 화면과 주요 동작은 검토용 초안인 [UI/UX 프로토타입](../design/README.md)에서 검토한다. 요구사항과 화면·상태의 연결은 [요구사항 추적표](../design/REQUIREMENTS_TRACE.md)에서 관리한다.

프로토타입 검토에서 제품 동작 변경에 합의하면 이 문서에 반영한 뒤 확정 사항으로 사용한다.

## 1. 프로젝트 방향과 사용 환경

- 작은 기능부터 시작해 필요할 때 기능을 추가한다. 최적화는 실제 문제가 관찰된 뒤 진행하며, 메시지큐·캐시·Redis도 필요가 확인된 뒤 도입한다.
- 사용자의 노트북에서 Docker로 실행하고, 집 Wi-Fi에 연결된 기기에서만 접속한다.
- 개인 사용자 1명이 간단한 로그인으로 사용한다. PC와 휴대폰 화면을 지원한다.
- 화면은 다크모드를 기본으로 한다.
- aiTrade 로고는 PC와 모바일 모두 상단에만 표시한다.
- PC 화면은 820px 초과에서 우측에 고정된 52px 아이콘 레일을 사용한다.
- PC 레일의 첫 아이콘 버튼은 화면 상단에서 8px 아래에 배치한다.
- 처음 열거나 새로고침하면 PC 메뉴 패널은 모두 닫힌 상태로 시작한다.
- AI 트레이더·체결 알림 중 선택한 하나의 패널만 아이콘 레일 왼쪽에 표시한다.
- PC 메뉴 패널은 너비 260px·레일과 간격 8px의 세로 패널로 본문 위에 표시한다.
- PC 메뉴 패널을 열거나 닫아도 본문 폭·로고·아이콘 위치를 유지한다.
- 다른 패널 아이콘을 선택하면 열린 패널을 선택한 패널로 바꾼다.
- 같은 패널 아이콘을 다시 선택하거나 패널 닫기 버튼·바깥 클릭·Escape를 사용하면 패널을 닫는다.
- 닫힌 패널 콘텐츠는 키보드 접근을 차단한다.
- 본문 이동 없이 패널을 닫을 때, 패널 안에 포커스가 있으면 해당 패널 아이콘으로 포커스를 돌려준다.
- 종목·투자 현황 아이콘을 선택하면 해당 본문으로 이동하고 열린 메뉴 패널을 닫는다.
- PC 아이콘 레일 하단에는 개인 프로필을 유지한다.
- PC 메뉴 패널에서는 목록만 내부 스크롤한다.
- PC 창이 너무 낮아 아이콘·프로필을 함께 표시할 수 없으면 레일을 스크롤해 모든 항목에 접근한다.
- 820px 이하에서는 모바일 하단 내비게이션을 사용한다.
- PC·모바일 화면 경계를 넘으면 열린 메뉴 패널을 닫는다.
- 클라우드 외부 배포 시점은 사용자가 완성도를 판단해 결정한다.
- 기능의 문제·해결 방법·수치 개선·최종 결과를 [성장 기록](GROWTH_LOG.md)에 남긴다.

### 증권사와 대상 자산

| 구분 | 역할 |
|---|---|
| 토스증권 | 주식 매매, 보유종목·주문·거래내역 조회, 필요한 시장 정보 조회 |
| KIS | 실전 계좌를 통한 시장 정보 조회 전용 |

1차 대상은 **국내 주식·국내 ETF·미국 주식**이다. 해외 ETF는 후속으로 추가한다.

### 금액 표시와 환율

- 화면의 모든 금액은 **원 단위(KRW)**로 표시한다. 해외 종목의 현재가·등락 금액·평균매입가·평가액·손익·세금·수수료·현금·주문가격·주문금액·평균 체결가격·거래금액도 원화로 환산한다.
- 원통화·원통화 금액·적용 환율·환율 기준 시각은 내부에 보존한다. 표시 환산 시 거래 통화를 유지하고 실제 환전은 실행하지 않는다.
- 해외 시세의 현재가와 등락 기준 가격은 **같은 비교 시점의 환율**로 환산해 등락 금액을 표시한다. 시세 등락률은 기존 시장 가격 기준으로 유지하며, 환율 변화에 따른 투자성과와 구분한다.
- 현재 자산·보유 요약은 **같은 평가 시점의 환율**로 외화 현금·보유 매입원가·평가액·비용·평가손익을 환산한 뒤 합산한다. 개인·AI별 합계와 전체 합계에도 같은 평가 환율을 사용한다. 평가 시각과 환율 기준 시각은 구분해 기록한다.
- 과거 주문·거래·실현손익과 성과 평가 기록은 **당시 기록된 환율**을 유지한다. 최신 환율로 과거 기록을 다시 표시하지 않는다. 필요한 당시 환율을 확인하지 못하면 해당 원화 금액은 ‘확인 불가’로 표시한다.
- 해외 주문·정정 가격도 **원화 입력**을 기본으로 한다. 실제 USD 주문가격으로의 역환산, 환율 적용 시점·호가단위·반올림 검증은 **API 확인 필요**이며, 실제 주문 제출 규칙은 API 확인 후 확정한다. 환율 출처·갱신 주기·지연 여부 확인 방법도 API 확인 후 정한다.

프로토타입의 환산 검토 기준과 구현 상태는 다음과 같다.

- 환산 검토에는 **검토용 고정 환율 1 USD = 1,350원, 기준 시각 2026.09.22 10:30 KST**를 적용한다.
- 과거 모의 거래는 각 기록에 명시한 모의 환율로 표시하며 현재 환율로 대체하지 않는다.
- 모의 주문·정정은 원화 입력을 시연한다. 정정 시 원래 USD 주문가격을 보존하고 원화 요청가격을 `krwPrice`로 별도 저장한다.
- 실제 환율 조회·USD 주문가격 역환산·주문 API 연동은 구현·검증 전이다.

## 2. 1차: 관심종목 관리와 실시간 시세

### 화면

메인 화면의 이름은 **종목**이다. 1차에는 관심종목 목록과 시장별 장 상태를 표시한다. 보유 탭과 개별 종목 상세는 2차에 추가한다.

### 이름 검색과 추가

- 종목 추가를 선택하면 현재 화면 위에 검색 화면이 열린다.
- 이름을 입력하거나 수정할 때마다 해당 입력에 맞는 종목 결과가 표시된다.
- 검색 결과를 선택해 관심종목에 추가한다.
- 추가에 성공하면 성공 여부를 표시하고 검색 화면을 유지해 다른 종목을 계속 검색·추가할 수 있게 한다.
- 검색 결과에 종목명·종목코드/티커·시장을 표시한다. 이미 관심목록에 등록된 종목은 ‘등록됨’으로 표시하고 중복 추가를 막는다.
- 검색 중에는 로딩을 표시하고, 결과가 없으면 ‘검색 결과 없음’을 표시한다. 검색 요청이 실패하면 오류와 재시도 버튼을 표시한다.
- 검색 화면을 닫으면 기존 관심목록의 스크롤 위치와 순서를 유지한다.

첨부한 검색 화면은 입력창과 결과 목록이 기존 화면 위에 뜨는 방식을 참고한다.

### 관심종목 관리

- 등록한 관심종목을 제거할 수 있다.
- 사용자가 목록 순서를 변경할 수 있다. PC와 휴대폰 모두에서 조작할 수 있어야 한다.
- 순서를 변경할 때 잡은 항목은 약간 반투명하게 표시하고, 목록의 보이는 영역 안에서 위아래로만 움직이게 한다. 목록에는 항목이 들어갈 자리를 표시한다. 키보드로도 항목을 이동할 수 있어야 한다.
- 순서 변경을 저장하면 새 순서를 반영하고, 취소하면 기존 순서를 유지한다.
- 관심종목과 순서는 노트북 서버에 저장하며, 새로고침·앱 재시작 후에도 유지한다. PC와 휴대폰은 같은 목록을 사용한다.
- 화면을 열거나 새로고침하면 다른 기기에서 변경한 목록을 반영한다. 열린 화면의 목록은 즉시 동기화하지 않는다. 목록 변경과 별개로 주가의 실시간 갱신은 유지한다.

### 실시간 시세

토스증권을 기본 시세 출처로 사용하고, 토스에서 제공하지 않는 정보만 KIS로 보완한다. 같은 종목의 현재가와 등락 기준 가격은 같은 출처를 사용한다. 1차에는 장애 시 증권사를 자동 전환하지 않는다.

관심종목마다 다음을 표시한다.

| 항목 | 의미 |
|---|---|
| 현재가 | 해당 종목의 최신 제공 가격을 원 단위로 표시 |
| 등락 금액 | 기준 가격에서 얼마나 올랐거나 내렸는지, 현재가와 같은 비교 환율을 적용해 원 단위로 표시 |
| 등락률 | 같은 기준 가격 대비 변화율을 퍼센트로 표시 |
| 등락 방향 | 국내·미국 모두 상승 빨강·하락 파랑·보합 회색으로 표시. 등락 금액과 등락률에 상승은 `+`, 하락은 `−` 부호 표시 |

등락 금액과 등락률은 각 시장의 **직전 거래일 정규장 종가**를 기준으로 계산한다. 같은 거래일의 정규장·시간외 모두 이 기준을 유지하며, 다음 거래일이 시작되면 기준 가격을 갱신한다. 거래일 구분은 해당 시장의 장 캘린더를 따르며 한국시간 자정에 임의로 기준을 바꾸지 않는다.

예를 들어 직전 거래일 종가가 100 USD, 오늘 정규장 종가가 110 USD, 오늘 시간외 가격이 108 USD이고 같은 비교 환율이 1 USD = 1,350원이면, 시간외 현재가는 145,800원, 전일 대비 등락은 `+10,800원`, `+8%`로 표시한다.

- 종목 목록에는 정상 수신 시각이나 조회 주기를 반복 표시하지 않는다. 연결 끊김은 해당 행에 표시하고, 종목별 수신 시각은 상세 화면에서 확인한다. 종목 목록·상세에는 지연 시간 문구를 표시하지 않는다.
- 종목별 시세는 실제 수신 시각을 유지한다. 전체 종목이 동일 시점의 스냅샷임을 확인한 경우에만 공통 시각을 표시한다.
- 시세 연결이 끊기면 마지막 수신 가격과 등락을 유지하고 목록에 ‘연결 끊김’, 상세 화면에 종목별 마지막 수신 시각을 표시한다.
- 자동 재연결을 시도하며, 재연결 후 해당 종목의 최신 시세를 받은 뒤 정상 표시로 돌아간다.
- 실시간 스트리밍이 없고 조회 API가 가격을 제공하는 종목은 내부적으로 주기 조회한다. 조회 방식·주기·지연 시간 문구는 종목 목록·상세에 표시하지 않는다.
- 원천 데이터의 지연 여부와 종목별 수신 시각은 내부 시세 정보에 유지한다. 투자 현황·AI 보유 표의 지연 표시는 별도 규칙을 따른다.
- 실제 조회 주기는 API 지원과 호출 한도를 확인한 뒤 정한다.

### 장 상태와 시간

- 국내와 미국의 장 상태를 각각 확인할 수 있어야 한다.
- 1차부터 API가 제공하는 **정규장·시간외 등 모든 세션**의 장 상태와 시세를 표시한다. 실제 지원 세션은 연동 시 확인한다.
- 현재 어떤 장이 진행 중인지, 그 장의 시작·종료 일시와 시간대를 표시한다.
- 시간은 **한국시간(KST)**을 기본으로 한다. 자정을 넘는 세션은 날짜도 표시해 시작·종료를 구분한다.
- 거래시간 외·휴장·장 정보 확인 실패를 구분해 표시한다.
- 상단의 거래시간 외 표시는 글자·배경·상태 점을 회색 계열로 낮춰 비활성 상태를 구분한다.
- 거래시간 외·휴장 상태에서 다음 세션 시작 일시를 확인할 수 있으면 함께 표시한다.
- 장 정보 확인에 실패하면 재시도 버튼을 표시한다. 실패를 휴장이나 거래시간 외로 표시하지 않는다.

## 3. 2차: 보유종목과 수동매매

### 목록과 상세 화면

- 종목 화면에 **관심 / 보유** 탭을 추가한다.
- 관심·보유, 투자 현황의 전체·개인, 투자 현황·AI 상세의 보유종목·손익·주문·거래 탭은 같은 선택 스타일을 사용한다.
- 탭을 선택하면 회색 선택 배경만 새 탭으로 짧게 이동한다.
- 탭의 글자와 키보드 포커스는 유지한다.
- 처음 표시하거나 같은 탭을 다시 선택할 때는 선택 배경을 즉시 표시한다.
- 동작 줄이기 설정에서는 선택 배경을 즉시 표시한다.
- 관심 탭은 사용자가 등록한 종목, 보유 탭은 토스 계좌에서 실제 보유한 종목을 보여준다.
- 관심·보유 탭을 선택하면 상세를 닫고 해당 목록만 표시한다. 첫 종목의 상세를 자동으로 열지 않는다.
- 종목을 선택하면 PC에서는 **우측 상세 패널**, 휴대폰에서는 **전체 너비 상세 화면**을 연다. 두 화면 모두 닫기 버튼을 제공한다.
- 관심·보유 목록의 종목 행 전체를 클릭하거나 키보드 Enter·Space로 선택할 수 있게 한다.
- 종목 행의 화살표는 이동 안내로 유지하고 별도 버튼 기능은 제공하지 않는다.
- PC에서는 상세 패널을 열어 둔 채 목록의 다른 종목을 선택할 수 있다.

관심 등록 여부와 보유 여부는 독립적이다. 보유한 종목이 관심 목록에 없을 수 있으며, 관심에서 제거해도 보유종목은 유지한다.

### 보유 정보와 주문 입력

종목 상세에서 자신의 보유 정보를 확인하고 매수·매도할 수 있어야 한다. 처음에는 다음 정보를 표시하며, 차트·호가창은 후속으로 추가한다.

| 영역 | 표시 정보 |
|---|---|
| 종목 | 이름·코드/티커·시장·원화 현재가·등락 금액·등락률(1차와 같은 기준) |
| 내 보유 | 보유수량·평균매입가 |
| 주문 입력 | 매수/매도 구분·가격·수량·예상 주문금액 |

세금·수수료와 평가손익은 투자 현황의 손익 상세에서만 확인한다. 종목 상세 주문 화면은 보유 정보와 가격·수량·예상 주문금액에 집중한다. 예상 비용과 확인되지 않은 값은 아래 손익 표시 규칙에 따른다.

평균매입가와 예상 주문금액은 위 공통 원화 표시 기준을 따르고, 해외 주문·정정 가격도 원화로 입력한다. 실제 USD 주문가격으로 역환산하는 절차·환율 적용 시점·호가단위·반올림 검증은 API 확인이 필요하다.

사용자가 가격과 수량을 정해 토스증권으로 지정가 매수·매도 주문을 제출한다. 2차의 첫 버전은 지정가 주문만 지원하며, 시장가 주문은 후속으로 추가한다.

- 2차부터 정규장과 시간외를 포함하되, 토스 API에서 지정가 주문 지원이 확인된 세션·종목에서만 주문을 제공한다. 시세 제공이나 장 운영 시간 조회만으로 주문 가능 여부를 판단하지 않는다.
- 각 세션의 접수 가능 시간·미체결 주문 만료·다음 세션으로의 이월 규칙을 확인한 뒤 활성화한다. 미확인 세션에서는 주문 제출을 비활성화하고 ‘주문 지원 확인 전’으로 표시한다.
- 토스 API가 지원하지 않는 국내 장전·장후 시간외종가 주문은 제외한다. 미국 시간외 세션과 국내 시간외 단일가 주문의 지원 여부는 추가 확인이 필요하다.
- 2차 첫 버전에 미체결 잔여수량 취소와 토스 API가 허용하는 가격·수량 정정을 포함한다. 이미 체결된 수량은 정정·취소 대상에서 제외한다.
- 정정 시 선택한 주문의 투자 주체·체결·잔여수량을 표시한다. 사용자가 허용된 변경값을 입력하면 변경 전후를 확인하게 한다.
- 사용자가 최종 확인하면 정정 요청을 보내고 주문 조회 결과로 상태를 확인한다.
- 해당 종목·세션·주문에서 지원하지 않는 정정 항목은 입력·제출을 막는다. 실제 허용 항목·범위·응답 방식은 API 확인이 필요하다.

### 주문 입력 중 종목 전환

- 주문 가격이나 수량을 입력한 상태에서 다른 종목을 선택하면 입력 중인 주문을 지우고 이동할지 확인한다.
- 동의하면 기존 입력을 지우고 새 종목으로 이동하며, 새 종목의 주문 입력을 초기화한다. 취소하면 기존 종목과 입력을 유지한다.
- 가격·수량을 아직 입력하지 않았다면 확인 없이 바로 이동한다. 종목별 주문 초안을 임시 보관하거나 복원하지 않는다.
- 종목 전환과 입력 초기화는 이미 제출한 주문을 정정하거나 취소하지 않는다.

### 주문 제출과 접수 확인

- 제출 전에 종목·매수/매도·가격·수량·예상 주문금액을 확인하고, 사용자가 확인한 뒤 주문을 제출한다.
- 주문 전송 중에는 동일 주문의 중복 제출을 막는다.
- 응답이 끊기는 등 접수 결과가 불명확하면 ‘접수 확인 중’을 표시하고 주문 조회로 접수 여부를 확인한다. 접수 여부가 확인되기 전에는 같은 주문을 자동으로 다시 보내지 않는다.

### 주문과 거래내역

주문 정보와 거래내역은 투자 현황의 전체·개인 및 AI 트레이더 상세의 `주문·거래` 탭에서 확인한다.

- 2차 첫 버전은 주문 단위로 표시하며, 개별 체결 이벤트 수집·표시는 포함하지 않는다.
- 각 목록에서 정정·취소할 수 있는 주문의 미체결 잔여수량을 확인할 수 있어야 한다.
- 전체 현황에는 각 주문의 투자 주체를 함께 표시한다.

| 구분 | 표시 정보 |
|---|---|
| 주문 | 종목·매수/매도·주문가격·주문수량·체결수량·잔여수량·상태·주문시각 |
| 거래내역 | 종목·매수/매도·원화 평균 체결가격·총 체결수량·체결 결과·마지막 체결시각 |

주문 접수와 체결은 구분한다. 하나의 주문이 여러 번 나누어 체결되어도 거래내역에는 주문 1건을 1행으로 표시한다. 평균 체결가격과 총 체결수량은 그 주문에서 실제 체결된 수량만 대상으로 하며, 마지막 체결시각은 가장 최근 체결의 시각이다. 미체결 수량은 거래내역에 포함하지 않고, 부분체결 후 잔여수량을 취소한 주문도 실제 체결 결과를 유지해 표시한다.

주문·거래의 가격과 금액은 당시 기록된 환율로 원화 표시하고, 원통화 가격·금액과 해당 환율·기준 시각은 보존한다. 당시 환율이 없는 과거 기록은 현재 환율로 대체하지 않고 원화 금액을 ‘확인 불가’로 표시한다.

- 거래내역은 기본으로 최근 1개월을 표시한다. 기존 시작일·종료일·시장 조회 조건을 유지하고 토스 API가 제공하는 범위에서 과거 내역을 조회한다.
- 거래내역은 영역 안에서 스크롤해 읽는다.
- 내부 스크롤 하단에 도달하면 과거 거래내역 10건을 기존 목록 뒤에 추가한다.
- 첫 표시·높이 확장·화면 복원·기간/시장 조회 초기화 후 스크롤이 없고 다음 거래내역이 있으면 10건씩 추가한다.
- 세로 스크롤이 생기거나 거래내역 끝에 도달하면 자동 추가를 멈춘다.
- 거래내역을 추가해도 읽던 위치를 유지한다.
- 실제 구현 전 거래내역 API의 페이지 경계·중복 제거·종료 신호를 확인한다.
- 거래내역 하단 손잡이를 위아래로 드래그해 내부 영역 높이를 조절한다. 화면 가장자리에 포인터를 유지하면 페이지를 함께 스크롤하며 높이를 계속 조절한다.
- 키보드 위·아래 화살표로도 높이를 바꾸고 Home·End로 최소·최대 높이를 선택한다. 전체·개인·AI 트레이더·새 초안 모두 같은 구조를 사용한다. 조회 결과가 없어도 빈 상태와 높이 조절 손잡이를 유지한다.
- 화면이나 주체를 전환했다가 돌아오면 주체별 거래내역 높이·불러온 수·읽던 스크롤 위치를 유지한다.
- 기간·시장 조회를 적용하면 추가 조회 범위와 스크롤을 처음으로 되돌리고 설정한 높이는 유지한다.
- 프로토타입은 모의 거래내역으로 이 흐름을 시연하며 실제 API 조회와 구분한다.

### 알림

- 2차 첫 버전은 앱이 열려 있을 때 개인·AI의 실제 체결 결과를 앱 내부 카드로 알린다.
- 접수·거부 알림, 읽음 처리, 미읽음 개수, 알림 전용 페이지는 제공하지 않는다.
- PC에서는 알림 아이콘을 선택해 아이콘 레일 왼쪽의 체결 알림 패널을 연다.
- 체결 알림은 최신순으로 표시한다.
- 알림 개수가 바뀌어도 상단 내비게이션 위치는 유지한다.
- 체결 알림은 최근 5개로 제한하지 않고 목록 안에서 스크롤해 확인한다.
- PC·모바일 알림 아이콘의 오른쪽 위에 붉은 원형 배지와 흰 숫자로 현재 목록에 남은 카드 수를 표시한다.
- 남은 카드가 0개면 숫자 배지를 숨긴다.
- 남은 카드가 1~99개면 해당 숫자를 표시하고 100개 이상이면 조금 넓힌 둥근 배지에 `99+`를 표시한다.
- 알림 버튼의 접근 가능한 이름·툴팁에는 정확한 전체 카드 수를 표시한다.
- 카드의 세로 여백을 줄여 체결 정보를 두 줄로 압축한다.
- 첫 줄에는 투자 주체의 개인·AI 이름을 왼쪽에, 체결시각을 오른쪽에 표시한다.
- 둘째 줄에는 종목·매수/매도를 왼쪽에, `체결수량 / 원화 주당 체결가격`을 오른쪽 그룹으로 표시한다.
- 주당 체결가격은 체결시각과 같은 오른쪽 여백·끝선에 정렬한다.
- 각 줄 안에서 글자 크기와 텍스트 기준선을 맞춘다.
- 체결시각은 오른쪽에 정렬하고 카드 안쪽의 개별 X 조작 영역과 겹치지 않게 한다.
- 주당 체결가격의 의미는 카드의 접근 가능한 이름·가격 툴팁에도 유지한다.
- 내용이 길면 정보를 생략하지 않고 요약 행의 줄바꿈을 허용한다.
- 새 카드는 오른쪽에서 한 번 진입한다.
- 같은 카드는 화면 전환·재렌더·목록 재개방 때 진입 효과를 반복하지 않는다.
- 개별 카드 안쪽 오른쪽 위의 작은 X 버튼으로 해당 알림을 목록에서 지울 수 있게 한다.
- 마우스를 사용할 때 개별 X는 카드에 포인터가 있거나 키보드 포커스가 표시된 동안 보인다.
- 마우스로 개별 알림을 지운 뒤에는 다른 카드로 포커스를 자동 이동하지 않는다.
- 마우스 삭제 후 포인터가 카드를 벗어나면 개별 X를 숨긴다.
- 키보드로 개별 알림을 지운 뒤 남은 이웃 카드가 있으면 그 카드로 포커스를 이어간다.
- PC 개별 X 버튼은 26px × 26px이며 카드 안쪽 위 5px·오른쪽 4px에 배치한다.
- 개별 X의 12px SVG는 조작 영역 중앙에 정렬한다.
- PC 카드 본문의 오른쪽 여백은 38px로 두어 체결시각·가격의 끝선을 맞추고 X 버튼과 8px 간격을 확보한다.
- 목록의 위 여백은 4px이며 나머지 안쪽 여백은 0으로 둔다.
- 카드 사이 간격은 12px로 유지한다.
- 목록 제목 오른쪽의 한글 `전체 지우기` 텍스트 버튼으로 현재 알림을 모두 지울 수 있게 한다.
- 개별 X는 반투명 흰색으로 표시한다.
- 개별 X 버튼의 배경과 장식 테두리는 생략한다.
- 개별 X의 키보드 포커스는 조작 영역 안쪽에 두께 2px·모서리 반경 6px의 흰색 윤곽선으로 표시한다.
- 전체 지우기 버튼은 중립색 글자로 표시한다.
- 전체 지우기 버튼의 장식 테두리와 기본 배경은 생략한다.
- 전체 지우기 버튼의 hover·키보드 포커스에는 밝은 글자와 옅은 중립색 배경을 표시한다.
- 전체 지우기 버튼의 키보드 포커스는 흰색 윤곽선으로 표시한다.
- 전체 지우기 버튼 높이는 PC 32px·모바일 44px로 유지한다.
- 알림 목록이 비어 있으면 전체 지우기 버튼을 비활성화한다.
- 전체 지우기는 목록 아래의 오래된 카드부터 왼쪽으로 순차 제거한다.
- 알림을 지워도 주문·거래 기록은 유지한다.
- 전체 지우기 도중 도착한 새 알림은 유지한다.
- 개인 카드를 선택하면 개인 투자 현황의 `주문·거래` 탭으로 이동한다.
- AI 카드를 선택하면 해당 AI 상세의 `주문·거래` 탭으로 이동한다.
- PC 알림 카드를 선택하면 체결 알림 패널을 닫고 이동한 본문에 포커스를 둔다.
- AI 이름을 수정해도 같은 트레이더 식별자로 알림의 귀속과 이동 대상을 유지한다.
- PC 아이콘 레일에는 AI 아이콘과 알림 아이콘 사이에 구분선을 표시한다.
- PC 알림 아이콘은 AI 아이콘 바로 아래 구분선 다음에 표시한다.
- 모바일 하단 네 번째 알림 메뉴는 PC와 같은 목록을 대화상자 패널로 연다.
- 모바일 목록의 최대 높이는 화면 높이와 패널 여백에 맞추고 목록 안에서 스크롤한다.
- 모바일 카드도 같은 정보 배치를 사용하고 개별 X를 항상 표시한다.
- 모바일 알림 패널의 개별 X 조작 영역은 44px × 44px로 유지하고 카드 안쪽 위 0·오른쪽 0에 배치한다.
- 모바일 카드 본문의 오른쪽 여백은 52px로 유지하고 X SVG는 PC와 같은 12px로 표시한다.
- 모바일 알림 패널은 바깥 클릭·Escape로 닫을 수 있게 한다.
- 동작 줄이기 설정에서는 카드 진입·삭제를 즉시 처리한다.
- 프로토타입은 모의 체결 카드와 세션 내 삭제 상태로 시연한다.
- 프로토타입에서 지운 알림은 화면 전환·재렌더 때 복원하지 않으며 새로고침하면 초기 모의 목록으로 돌아간다.
- 실제 체결 알림 연결은 제품 구현 전이다.
- 실제 체결 정보의 수집 단위·중복 구분은 API 확인 후 구체화한다.
- 체결 카드 시연으로 위 주문·거래내역의 주문 단위 기록 범위를 확대하지 않는다.
- 앱 화면을 닫으면 알림을 전달하지 않는다. 다시 열면 최신 주문·체결 상태를 조회해 표시한다.
- 화면을 닫아도 PC·휴대폰에서 받을 수 있는 외부 알림은 후속으로 추가한다.

## 4. 3차: AI 자동매매

### 초기 목표

- AI가 토스증권·KIS에서 필요한 정보를 가져와 종목과 매매 시점을 판단하고, 토스증권을 통해 실제 거래한다.
- **AI 선정** 모드의 트레이더는 매 판단마다 투자 범위 안에서 관심종목 밖의 종목도 투자 후보로 탐색한다. 관심 목록은 사용자가 관찰하는 종목을 관리한다.
- 첫 전략의 투자 대상은 국내 주식·국내 ETF다. 미국 주식 자동매매는 후속으로 추가한다. 이 범위는 자동매매에만 적용하며, 1차 시세와 2차 수동매매의 미국 주식 범위는 유지한다.
- 3차 첫 버전부터 성향이 다른 여러 **AI 트레이더**를 추가하고 개별 운영할 수 있게 한다. 각 트레이더는 자신의 운용금액으로 종목과 매매 시점을 결정한다.
- 초기 운영은 중기 트레이더 1명·전략 1개로 시작한다. 검증하며 다른 성향의 트레이더를 추가하고, 전략 간 피드백은 후속으로 구현한다.
- AI 선정 모드에서는 서버의 조회 도구로 매 판단마다 투자 범위 안의 종목을 탐색한다. 필요한 종목 데이터를 요청해 투자 후보를 선택한다.
- 직접 선택 모드에서는 저장된 종목 안에서 후보를 판단하고 매매한다.
- 탐색에 사용한 조회와 후보 선택 근거를 기록한다. 현재 보유종목은 탐색 결과와 관계없이 판단에 포함한다.
- 제공할 탐색 도구와 탐색 종료 조건은 **보류**하고 후속 논의에서 정한다.
- AI가 종목·매수/매도/관망·주문가격·주문수량·판단 근거를 결정한다. 관망에는 주문을 제출하지 않는다.
- 서버는 트레이더의 투자대상 범위·거래 가능 여부·사용 가능한 자금·보유수량을 검사한다. 검사를 통과한 판단만 토스증권으로 주문한다. 조회 도구는 주문 실행 권한을 갖지 않는다.
- 판단에 사용하는 정보와 근거는 최소로 시작한다. 첫 전략의 구체적인 판단 기준·지표는 미정이다.
- 첫 전략에는 각 모드의 후보 종목에 대한 현재가·최근 일봉 가격/거래량, 해당 AI 트레이더의 보유·미체결 주문·운용금액을 제공한다. 일봉 조회 기간과 AI의 후보 선택 기준은 미정이다.
- 이후 각종 보조지표·기업 정보·뉴스·공시·재무정보 등을 수집해 판단 입력에 포함한다. 초기 입력과 추가한 정보를 구분해 기록하여 정보 추가 전후의 판단과 결과를 비교할 수 있게 한다.
- 판단 근거와 실제 거래 결과를 남겨 어떤 판단이 어떤 결과로 이어졌는지 확인할 수 있어야 한다.
- 실제 자동매매를 시작하기 전에 탐색 도구·종료 조건·AI의 후보 선택 기준과 트레이더별 실제 운용금액을 정한다.

### AI 트레이더별 자금과 기록

- 하나의 AI 트레이더 생성 화면에서 이름·투자 유형·최초 배정금·종목 선정 방식·투자대상을 입력한다. 종목 선정 방식은 **AI 선정 / 직접 선택**, 투자 유형은 **초단타·중기·장기 중 하나**를 선택한다. 매매 스타일·선호 지표 등 다른 성향 항목이나 자유 설명 입력은 요구하지 않는다.
- 생성 화면의 이름·유형·배정금은 매번 빈 상태로 시작하고 유형은 사용자가 선택한다.
- 생성할 때 기본정보의 누락·이름 중복·금액 오류와 투자대상을 함께 검사하고 대화상자 안에서 안내한다.
- 선정 방식을 전환하면 입력과 임시 선택을 유지한다. 취소하거나 닫으면 입력 검사 없이 임시값을 폐기한다. 다시 열면 빈 기본정보와 기본 선정 방식으로 초기화한다.
- 생성 화면에는 개인의 미투자 현금과 주문에 묶인 현금, 두 금액의 차이인 최대 배정 가능 금액을 표시한다.
- 최초 배정금이 개인의 사용 가능 현금을 초과하면 생성하지 않는다. 생성 시 개인 현금을 차감하고 새 AI 트레이더의 현금으로 옮기므로 전체 자산은 변하지 않는다.
- 투자대상 모드의 기본값은 **AI 선정**이다. 사용자는 종목을 지정하지 않고 생성할 수 있으며, AI가 매 판단마다 프로젝트의 투자 범위 안에서 후보를 자율 탐색한다. AI 선정으로 생성하거나 수정 내용을 저장할 때 직접 선택 목록은 빈 상태로 저장한다.
- **직접 선택**에서는 여러 종목을 검색하거나 현재 관심종목을 눌러 추가한다. 선택한 목록에서 개별 종목을 제거할 수 있으며 같은 종목은 한 번만 추가한다.
- 직접 선택 모드로 생성하거나 수정을 저장하려면 최소 한 종목이 필요하다. 선택 가능한 대상은 현재 자동매매 투자 범위인 국내 주식·국내 ETF다.
- 모드를 전환하는 동안 직접 선택한 임시 목록을 유지한다. 생성과 수정 저장에서는 선택한 모드와 그 모드의 투자대상만 저장한다. 직접 선택 목록은 트레이더 식별자별로 보존하고, 개인 관심목록의 추가·제거와 독립적으로 유지한다.
- 생성한 AI 트레이더와 초안은 상세의 투자대상 영역에서 선정 방식·종목 목록을 수정할 수 있다. 수정 화면은 선택한 트레이더의 현재 방식·목록으로 시작한다.
- 수정을 저장하면 해당 트레이더의 투자대상 설정만 갱신한다. 취소하거나 닫으면 임시 변경을 폐기하고 기존 설정을 유지한다. 다시 열면 저장된 설정을 표시한다.
- 위 생성·수정 흐름과 투자대상 기준은 확정 사항이다. 프로토타입에서 모의 종목 검색·관심종목의 투자대상 추가·선택 검증·생성·수정 저장 흐름을 검토한다. 모의 수정은 이름·투자 유형·배정금·현금·보유·주문을 유지한다.
- 실제 운영 중 변경 적용 시점과 기존 보유종목·미체결 주문 처리 정책은 **보류**한다. 실제 설정 저장·검색 API 연동·모드별 AI 후보 탐색·서버의 투자대상 주문 검사는 제품 구현 전이다.
- PC `AI 트레이더` 아이콘을 선택하면 본문을 유지하고 목록 패널만 연다.
- AI 트레이더 목록 패널에는 기존 트레이더·초안 목록과 추가 버튼을 표시한다.
- PC 목록에서 트레이더·초안을 선택하면 본문에 해당 상세를 표시하고 목록 패널을 유지한다.
- 본문 안에는 AI 트레이더 선택 목록을 반복하지 않는다.
- 모바일에서는 하단 `AI 트레이더` 메뉴에서 같은 목록과 추가·닫기 동작을 제공한다.
- AI 트레이더 메뉴 목록·초안·상세의 한 글자 아바타는 투자 유형을 따른다. 초단타는 `S`, 중기는 `M`, 장기는 `L`로 표시하고 이름 수정 시 유형 아바타는 유지한다.
- 생성 후 AI 트레이더와 초안의 이름을 수정할 수 있다. 메뉴 목록에서 대상을 선택한 뒤 상세 상단에서 수정하며, 목록 항목에는 별도의 수정 버튼을 두지 않는다.
- 이름 수정 시 빈 이름과 다른 AI 트레이더·초안의 중복 이름은 허용하지 않는다. 이름을 바꿔도 트레이더 식별자와 기존 자금·보유·주문·거래·성과의 귀속은 유지하고, 화면에는 새 이름을 일관되게 표시한다.
- 새 AI 트레이더 초안의 상세도 기존 트레이더와 같은 자산 요약·시간가중수익률·최근 판단 기록·보유종목 구조를 사용한다.
- 초안의 배정금은 초기 현금과 총 자산으로 표시한다. 투자금·보유 평가액·평가 순손익은 0으로 표시하며, 투자금이 없으므로 보유 수익률은 계산하지 않는다.
- 초안에 기록이 생기기 전까지 성과 그래프·판단 기록·보유종목은 빈 상태로 표시한다. 전략 기준이 확정되기 전까지 초안의 자동매매를 시작하지 않는다.
- 초안 상세에도 이름 수정·투자대상 수정·자금 관리·자동매매 시작 버튼을 같은 위치에 둔다. 자금 관리는 개인과 초안 사이의 사용 가능 현금을 이동하고 최초 배정금 이력은 유지한다. 자동매매 시작은 전략 기준이 확정되기 전까지 사용할 수 없음을 표시한다.
- 최근 판단 기록은 최신순으로 표시한다. 최신 기록의 점은 메인 민트색으로 강조하고, 바로 다음 점까지의 연결선은 기존 중립색으로 점차 옅어지게 표시한다. 나머지 점·연결선은 중립색을 유지한다.
- 판단 기록의 제목 옆에 종목명과 **매수·매도·기타** 분류 배지를 표시한다. 복수 보유종목 점검은 해당 종목명을 각각 표시하고, 자동매매 중지 같은 운영 기록은 **운영** 범위로 표시한다.
- 판단 기록의 분류·종목은 구조화된 기록 정보를 사용하며 제목 문구에서 추론하지 않는다. 실제 기록 데이터 연결은 제품 구현 전이다.
- 최근 판단 기록은 영역 안에서 스크롤해 읽는다. 영역 하단의 손잡이를 위아래로 드래그해 기록 영역 높이를 조절한다. 화면 가장자리에 포인터를 유지하면 페이지를 함께 스크롤하며 계속 조절한다.
- 키보드 위·아래 화살표로도 기록 영역 높이를 바꾸고 Home·End로 최소·최대 높이를 선택한다. 화면 높이에 맞는 범위 안에서 조절한다.
- 내부 스크롤이 하단에 도달하면 과거 판단 기록 10건을 이어서 불러오며 최신순을 유지한다.
- 추가된 판단 기록은 기존 목록 뒤에 붙이며 읽던 위치를 유지한다.
- 판단 기록에는 기간 검색을 제공하지 않는다.
- 화면이나 트레이더를 전환했다가 돌아오면 트레이더별 기록 영역 높이·불러온 기록 수·읽던 스크롤 위치를 유지한다. 새 트레이더 초안도 같은 기록 영역 구조를 사용하고 판단 기록이 생기기 전까지 빈 상태를 표시한다.
- 프로토타입의 이어보기는 모의 기록 시연이며 실제 API 조회와 구분한다.
- 투자 유형별 전략을 미리 정의하고 실제 AI 판단에 반영한다. 선택한 유형과 적용 전략을 기록해 어떤 설정으로 어떤 판단·거래·성과가 나왔는지 연결한다. 유형별 판단 기준과 필요한 데이터는 전략 설계 때 정하도록 **보류**한다.
- 초단타는 수초~수분 단위로 매매하고, 매수한 종목을 같은 거래일 안에 청산해 다음 거래일까지 보유하지 않는 유형이다. 당일 청산 시점과 미체결·거래 중단 등으로 청산하지 못한 경우의 처리 방식은 초단타 유형을 추가할 때 정하도록 **보류**한다.
- 중기는 수일~수주, 장기는 수개월 이상을 기본 보유기간으로 하는 유형이다. 보유기간은 유형별 전략 설계에서 정한다.
- 사용자가 AI 트레이더마다 원화 최초 배정금을 지정한다. AI는 배정금을 임의로 변경하거나 다른 트레이더의 자금을 사용할 수 없다.
- 초기 운용 설정은 운용금액과 투자대상을 지정한다. 1회 주문금액·종목별 투입금액 상한과 손실률에 따른 자동 중지 기준은 두지 않는다. AI는 배정받은 자산 범위에서만 주문할 수 있다.
- AI 트레이더별로 관리 종목·보유수량·금액·투자이익·주문·거래내역을 구분해 기록한다. 같은 종목을 여러 AI가 보유할 때도 각 트레이더의 수량과 거래 귀속을 구분해야 한다.
- 운용금액은 최초 배정금으로 기록하고 생성·이력에 보존한다. 현재 현금·보유자산은 별도로 기록한다.
- 거래 결과와 비용에 따라 해당 트레이더의 자산이 늘거나 줄며, 현재 사용 가능한 자금 범위에서 수익을 재투자할 수 있다. 재투자 시 최초 배정금 설정을 유지한다.
- 개인과 모든 AI 트레이더의 실제 주문은 토스 실계좌 하나를 사용한다. 앱 내부 장부에서 개인과 각 트레이더의 현금·보유수량·주문·거래·성과를 따로 관리한다.
- 주문 제출 전에 매수에 필요한 현금 또는 매도할 수량을 해당 투자 주체의 보유분에서 묶어 둔다. 개인 수동 주문·AI 자동 주문·AI 보유분의 수동 매도에 같은 규칙을 적용한다.
- 주문에 묶인 현금·수량은 다른 주문이나 자금 배정·회수에 중복 사용하지 못하게 한다.
- 체결된 부분은 실제 거래 결과대로 현금·보유수량에 반영하고, 미체결 부분은 계속 묶어 둔다.
- 전량 체결·취소·거절 등으로 주문이 종료됐음을 확인하면 남은 예약 금액·수량을 해당 투자 주체가 다시 사용할 수 있게 한다. 주문 상태가 불명확하거나 취소 확인 중이면 종료를 확인할 때까지 묶인 상태를 유지한다.
- 같은 계좌의 현금이나 보유수량을 여러 트레이더에게 중복 배정하거나 주문에 중복 사용하지 못하게 관리한다.
- 자동매매 재개 전, 체결 반영 후, 자금 배정·회수 후에는 개인과 모든 AI의 현금·보유수량 장부 합계를 실제 계좌와 대조한다.
- 앱 장부와 실제 계좌가 불일치하면 모든 AI 트레이더의 신규 자동 주문을 차단하고 사용자에게 불일치를 표시한다. 이미 시작한 AI 판단의 결과도 새 주문으로 제출하지 않는다.
- 불일치 원인을 확인·해소하고 장부와 실제 계좌가 일치함을 다시 확인한 뒤 사용자가 재개한다.
- 불일치로 차단된 동안에는 기존 주문을 유지하고 상태 확인을 계속한다. 사용자가 AI 중지를 요청하면 아래 주문 취소 규칙을 적용한다.
- AI에 현금을 배정하면 개인 장부의 현금에서 해당 금액을 차감하고 해당 AI의 현금으로 기록한다. 배정 자체는 실제 계좌의 총현금을 바꾸지 않으며 투자수익으로 계산하지 않는다. 기존 개인 보유종목은 개인에 귀속한다.
- 사용자가 추가 자금 배정·회수를 요청하면 해당 AI의 중지 처리가 완료된 뒤 주문과 현금을 확인한다. 개인과 해당 AI 사이에서 주문에 묶이지 않은 것으로 확인된 사용 가능 현금만 이동한다.
- 이동 가능한 현금을 넘는 배정·회수 요청은 실행하지 않는다. 회수를 위해 보유종목을 자동 매도하지 않는다.
- 추가 배정은 개인 현금을 차감해 해당 AI에 더하고, 회수는 해당 AI 현금을 차감해 개인에게 돌려준다. 최초 배정금은 유지하고 추가 배정·회수를 별도로 기록한다. 자금 이동은 투자수익·손실로 계산하지 않는다.
- 초기 운용에서 실계좌에 입금하면 개인 현금 장부에 먼저 반영하고 계좌와 대조한다. 그다음 개인의 사용 가능 현금 범위에서 AI 최초·추가 자금을 배정한다.
- 실계좌 입금은 전체 자산의 외부 자금 유입으로, AI 배정은 전체 자산을 바꾸지 않는 내부 이동으로 기록한다. AI TWR은 최초 배정 직후부터 계산한다.
- 별도의 실계좌 입출금 자동 감지와 입출금 기록 화면은 초기 범위에 포함하지 않는다.
- 개인·각 AI의 장부에서 비용 반영 전 매입원가는 투자 주체·종목별 **이동평균**으로 계산한다. 매수 체결 시 평균매입가는 `(현재 보유분의 매입원가 + 추가 매수 체결금액) / (현재 보유수량 + 추가 체결수량)`으로 갱신한다. 세금·수수료는 매입원가와 별도로 관리한다.
- 매도 체결 시 원가는 `해당 주체의 평균매입가 × 체결수량`으로 계산하고, 매도 체결금액과의 차이를 비용 반영 전 실현손익으로 기록한다. 남은 보유분의 평균매입가는 유지한다.
- 전량 매도하면 보유수량과 남은 매입원가는 0이 되며, 다음 매수부터 새 평균매입가를 계산한다. 미체결 주문은 평균매입가를 변경하지 않는다.
- 실제 매수 세금·수수료는 투자 주체·종목별로 남은 보유분에 귀속한다. 추가 매수 시 해당 보유분의 미배분 매수 비용에 새 매수 비용을 더한다.
- 일부 매도 시 세금·수수료 각각에 대해 `매도 직전 미배분 매수 비용 × 매도 체결수량 / 매도 직전 보유수량`을 실현손익 비용으로 배분한다. 나머지는 남은 보유분의 평가손익 비용으로 유지한다. 전량 매도 시 남은 매수 비용을 모두 실현손익에 배분한다.
- 실현 순손익은 비용 반영 전 실현손익에서 배분된 매수 비용과 실제 매도 체결의 세금·수수료를 차감한 금액이다. 보유분의 순평가손익에는 남은 매수 비용과 별도 표시한 예상 매도 비용을 반영한다. 비용 배분 자체로 현금을 다시 차감하지 않는다.
- 보유분의 예상 매도 비용은 **현재가로 남은 보유수량 전부를 매도한다고 가정**해 산정하고, 예상 세금·수수료·비용 합계를 순평가손익에 반영한다. 예상 비용은 현금에서 실제 차감하지 않는다. 적용 수수료·세금 정보의 출처와 구체적인 산식은 API 확인 후 정한다.
- 투자 현황의 전체·개인과 AI 트레이더별 상세의 첫 요약에는 같은 순서와 기준으로 **총 자산·미투자 현금·투자금·보유 평가액·평가 순손익·보유 수익률**만 표시한다. 최초 배정금은 생성·이력에 보존한다.
- 전체·개인과 기존·초안 AI 자산 요약은 공통 카드 컴포넌트·그리드를 사용한다.
- 자산 요약의 콘텐츠 폭·카드 높이·여백·배경·반응형 배치는 모든 투자 주체에서 같게 표시한다.
- 넓은 PC 화면의 자산 요약은 3열·2행으로 배치하며 좁은 화면에서는 공통 반응형 기준에 따라 열 수를 줄인다.
- 긴 금액은 생략하지 않고 줄바꿈한다.
- 총 자산은 현금 잔액과 보유 평가액의 합이다. 미투자 현금은 주문에 묶인 현금을 포함한 해당 주체의 현금 잔액이다.
- 투자금은 현재 보유분의 비용 반영 전 매입원가이며, 위 이동평균 장부의 남은 보유분을 기준으로 한다. 보유 평가액은 현재 보유수량의 시가 평가액이다.
- 평가 순손익은 보유 평가액과 투자금의 차이에서 현재 보유분에 귀속된 매수 비용과 예상 매도 비용을 뺀 금액이다. 예상 매도 비용은 별도로도 표시한다.
- 보유 수익률은 `평가 순손익 / 투자금 × 100`으로 계산한다. 현재 보유 매입원가가 0이면 보유 수익률은 표시하지 않는다.
- 현금과 이미 매도한 종목의 실현손익은 투자금·보유 평가액·평가 순손익·보유 수익률에서 제외한다. 실현손익과 총손익은 손익 상세에 별도로 표시한다.
- 예상 비용이나 필요한 매입원가를 확인하지 못하면 금액·비율을 확정하지 않는다. 2차 실제 계좌의 토스 제공 평가손익은 투자 주체별 귀속과 산출 기준을 확인한 뒤 적용 여부를 정한다.
- **개별 AI 트레이더의 운용 성과**는 시간가중수익률(TWR)로 계산하며, 투자 현황의 보유 수익률과 구분한다. 전체·개인의 TWR은 대표 지표로 제공하지 않는다.
- AI의 최초 배정 직후부터 성과를 측정한다. 해당 AI에 자금이 들어오거나 나가는 직전·직후의 자산 평가 기록을 남기고 구간별 수익률을 복리로 연결한다. 배정·회수 자체는 수익·손실로 계산하지 않는다.
- AI TWR의 자산 평가액은 **해당 AI의 현금 + 보유종목의 현재가 평가금액**이다. 주문에 묶인 현금·수량도 자산에 포함하되 중복 합산하지 않는다.
- 실제 발생한 거래 세금·수수료는 AI의 현금에 반영한다. 손익 계산을 위한 매수 비용 배분 때 현금을 다시 차감하지 않으며, TWR에서는 예상 매도 비용을 차감하지 않는다.
- 총 자산·미투자 현금·투자금·보유 평가액·평가 순손익·보유 수익률과 AI TWR은 위 공통 **원화 표시·평가 기준**을 따른다. 환율 변화는 원화 기준 AI TWR에 반영한다.
- 평가 기록마다 적용 환율·환율 기준 시각·평가 시각을 남긴다. 저장한 성과 평가 기록은 당시 환율로 보존하고 실제 환전은 실행하지 않는다.
- 외화 매입원가·비용·손익의 원천 데이터 제공과 환율 출처·갱신·지연 여부는 API 확인이 필요하다.
- AI의 실제 자산이 0이 되면 해당 운용기간을 종료하고 TWR을 보존한다. 전액 회수는 자금 이동으로 처리해 회수 자체를 손실로 계산하지 않으며, 투자 손실로 자산이 0이 되면 해당 기간의 손실을 유지한다. 사용 가능한 현금만 0이거나 평가 정보를 확인할 수 없는 경우는 자산 0으로 판단하지 않는다.
- AI 자산이 0인 동안에는 TWR을 계산하지 않고, 다시 자금이 들어오면 새 운용기간의 TWR 계산을 시작한다. 기간별 수익률은 따로 보존한다. 과거 거래내역·누적 실현손익·AI 최초 배정금 기록은 유지한다. AI 중지·재개 시 기존 운용기간을 유지한다.
- 개별 AI의 TWR 평가 기록은 **한국시간 매일 00:00과 해당 AI의 자금 이동 직전·직후**에 저장한다. 자정 기준 자산 평가이며 시장별 종가 기록과 구분한다. 종목의 전일 대비 등락 계산 기준은 유지한다.
- 초기에는 일정 간격의 장중 평가 기록을 추가로 저장하지 않는다. 주문·체결·AI 판단 기록은 발생할 때마다 별도로 남긴다.
- AI TWR 그래프에서 커서·터치·키보드로 기록을 선택하면 해당 평가 시각(KST)과 그 기록의 TWR 값을 표시한다. 툴팁은 저장된 평가 기록만 표시한다.
- TWR 그래프가 처음 나타나거나 다른 트레이더로 바뀌면 선과 은은한 민트 채움이 기준선에서 부드럽게 올라온다. 같은 차트의 탭·상태 변경에는 반복하지 않고, 시점 탐색을 시작하거나 동작 줄이기 설정을 사용하면 실제 기록 위치를 즉시 표시한다.
- 성과 그래프는 AI의 최초 배정 이후 운용기간을 표시한다. 운용 시작 후 서버 미실행 등으로 실제 일일 평가를 남기지 못한 날짜만 **‘기록 없음’**으로 표시한다.
- 누락 날짜에는 이전 평가값이나 재시작 시점의 값을 채우지 않는다. 초기에는 과거 평가 기록을 복원하지 않는다.
- 재시작 후 계좌·주문·시세를 확인하면 현재 평가를 실제 평가 시각으로 별도 기록한다. 다음 정기 평가는 한국시간 00:00에 진행한다. 이 평가 기록으로 자동매매를 재개하지 않는다.

### 투자 현황 화면

- 투자 현황 상단은 **전체·개인**으로 구분한다. 전체는 개인과 모든 AI를 포함하며, AI만 합산하는 별도 화면은 제공하지 않는다. 개별 AI의 자산과 내역은 AI 트레이더 메뉴에서 해당 트레이더를 선택해 확인한다.
- 전체·개인 선택에는 보유종목·손익·주문·거래 탭과 같은 스타일과 선택 배경 이동 효과를 적용한다.
- 전체·개인 또는 AI 주체를 바꾸면 하위 보유종목·손익·주문·거래 탭의 선택 배경은 즉시 표시한다.
- 전체 화면에는 개인과 모든 AI의 현금·보유종목·손익·주문·거래내역을 함께 표시한다. 합산 현황과 개인·각 AI별 내역을 확인할 수 있어야 한다.
- 첫 요약과 상세 현금·종목 가격·손익·주문·거래 금액은 모두 원화 표시 기준을 따른다. 원통화 잔액은 내부 장부에 구분해 보존한다. 전체 보유 수익률은 전체 평가 순손익을 전체 투자금으로 나눠 직접 계산한다.
- 전체 보유목록에서는 같은 종목의 총 보유수량과 개인·각 AI별 보유수량을 확인할 수 있어야 한다. 전체 주문·거래내역에는 각 항목의 투자 주체를 ‘개인’ 또는 AI 이름으로 표시한다.
- 보유종목 각 행에 종목 목록과 같은 시세의 현재가, 평균매입가, 현재가 기준 평가손익·수익률을 표시한다. 금액은 공통 원화 표시·평가 기준을 따른다. 지연 시세와 연결 끊김은 현재가 옆에서 구분한다.
- 개인·AI별 평균매입가는 해당 투자 주체의 보유분으로 계산한다. 전체 화면의 평균매입가는 투자 주체별 보유수량으로 가중한다.
- 보유 행의 평가손익·수익률은 현재 보유분의 비용 반영 전 값이다. 요약의 비용 반영 후 평가 순손익과 기준을 구분한다.
- 개인 현황에는 AI에 배정한 자금을 제외한 개인 귀속 현금·보유종목·손익·주문·거래내역만 표시한다. 개인 자금으로 한 매매는 개인에, AI 자금으로 한 매매는 해당 AI에 귀속한다.
- 개별 AI 트레이더 상세는 위 여섯 항목과 투자 유형·관리 종목·보유·손익·주문·거래내역을 표시한다. 투자 현황과 같은 **보유종목·손익·주문·거래** 탭을 같은 데이터와 동작으로 제공한다. 트레이더를 선택하면 해당 주체의 귀속 내역을 표시한다.
- 자금 관리 흐름에서 사용 가능 현금과 주문에 묶인 금액을 구분해 확인한다.
- 개별 AI 상세에는 별도의 TWR 값·추이 그래프·현재 낙폭·최대 낙폭도 표시한다. 현재·최대 낙폭은 저장된 성과 평가 기록의 TWR 흐름으로 계산하며 기록 사이의 장중 저점은 포함하지 않는다.
- 투자 현황의 개인 화면과 개별 AI 트레이더 상세는 선택한 주체의 현금·보유종목·손익·주문·거래내역을 같은 기준으로 표시한다. 화면에는 현재 선택된 개인 또는 AI 트레이더를 명확히 표시한다.
- 개인·개별 AI 화면에서 손익 금액은 **실현손익·평가손익·총손익**으로 구분해 표시한다. 실현손익은 실제 매도 체결로 확정된 손익, 평가손익은 현재 보유분의 평가에 따른 손익이며, 총손익 금액은 두 금액의 합이다. 미체결 매도 주문은 실현손익에 포함하지 않는다.
- 전체·개인 투자 현황과 개별 AI 상세의 손익 탭에는 **비용 반영 전 손익·세금·수수료·비용 합계·비용 반영 후 순손익**을 함께 표시한다. 비용 합계는 세금과 수수료의 합이며, 실현손익·평가손익·총손익 각각에서 비용 반영 전·후를 구분한다.
- 실제 체결에 대해 확인된 비용과 보유분 평가에 사용한 예상 비용을 구분한다. 같은 비용을 실현손익과 평가손익에 중복 반영하지 않는다.
- 손익 표의 금액 칸에는 숫자 오른쪽에 `원`을 붙여 표시한다. 표 아래에서 실현손익은 체결 기준, 평가손익은 현재 보유분 기준 예상값, 총손익은 두 항목의 합계임을 명시한다.
- 필요한 비용이나 적용 환율을 확인하지 못하면 해당 금액과 이를 계산에 필요로 하는 순손익에 ‘확인 불가’를 표시한다. API 계약상 비용이 없는 경우만 0으로 처리한다.
- 개인의 실현손익은 앱에서 개인 거래 기록을 관리하기 시작한 시점부터 누적한다. 과거 거래 손익 이관은 초기 범위에 포함하지 않는다. 개인의 평가손익은 현재 보유분을 기준으로 표시한다.
- AI의 실현손익은 최초 자금 배정 시점부터 누적하고, 평가손익은 현재 보유분을 기준으로 표시한다. 중지·재개해도 누적 기록을 초기화하지 않는다. 추가 자금 배정·회수 금액은 손익 집계에서 제외한다.
- 전체 보유목록에서 매도를 누르면 해당 종목을 보유한 개인·AI의 이름과 보유수량을 표시하고, 매도할 투자 주체 하나를 선택하게 한다. 개인을 선택하면 개인 매도 입력·주문 확인 절차로, AI를 선택하면 아래 AI 중지 확인·수동 매도 절차로 이어진다. 선택한 주체의 보유분만 매도 대상으로 한다.
- AI 보유목록의 각 종목에 매도 버튼을 제공한다. 해당 AI를 중지하고 모든 자동 주문의 종료를 확인한 뒤에만 수동 매도를 허용한다.
- 수동 매도 대상은 해당 AI의 보유분으로 한정한다. 실제 체결 결과를 그 AI의 보유수량·현금·손익·거래내역에 반영하고 ‘사용자 수동 매도’로 표시한다. 미체결 수량은 보유수량에서 차감하지 않는다.
- AI가 실행 중일 때 매도 버튼을 누르면 ‘AI를 중지하고 미체결 주문을 취소한 뒤 매도하시겠어요?’를 표시한다. 사용자가 동의하면 해당 AI의 중지 절차를 실행하고 중지 완료 후 매도 입력 화면을 연다.
- 이미 중지 완료 상태에서 매도 버튼을 누르면 바로 매도 입력 화면을 연다. 매도는 가격·수량 입력과 주문 확인 후 제출한다.
- 매도 절차를 끝내거나 중간에 닫아도 AI는 중지 상태를 유지한다.

### 판단 실행 시점

- 초기 중기 AI도 하루에 여러 번 후보·보유종목·주문 상태를 확인하고 판단한다. 구체적인 시간대와 간격은 매일·매월·특정 시기에 반복되는 시장 패턴을 전략에 어떻게 반영할지와 함께 정해야 하므로 **보류**한다.
- 정해진 조건이 발생하면 즉시 추가 판단을 요청한다. 초기 조건의 종류·기준값과 재판단 범위도 투자 전략과 함께 정하도록 **보류**한다.
- 정기 판단과 조건 판단이 겹치면 하나로 묶고, AI 판단은 동시에 여러 개 실행하지 않는다.
- 같은 조건이 계속 유지된다는 이유로 판단을 반복하지 않도록 재실행 대기시간과 조건 재발생 기준을 둔다. 구체적인 시간과 기준은 투자 전략과 함께 정하도록 **보류**한다.
- 조건이 발생하면 AI에 재판단을 요청한다. 재판단 결과가 해당 AI 트레이더의 투자대상 범위·거래 가능 여부·자금·보유수량 검사를 통과한 경우에만 주문을 제출한다.
- 초기 조건 감시와 판단 실행은 서버 안에서 처리한다. 메시지큐는 실제 필요가 관찰된 뒤 도입한다.

### 수동 주문과 자동 주문

- 자동 주문은 AI 트레이더별로 순서대로 제출한다. 각 주문의 접수 결과를 처리한 뒤 해당 AI의 다음 주문을 제출한다. 서로 다른 AI는 병렬 제출할 수 있다.
- 체결 상태는 주문별로 별도 확인한다. 병렬 제출에서도 트레이더별 현금·수량 예약과 실제 계좌의 사용 가능 금액·수량 검증을 적용한다. 판단 실행의 동시성은 위 판단 규칙을 유지한다.
- AI가 매도할 수 있는 수량은 해당 AI의 자동매매로 매수한 수량 중 아직 보유 중인 수량으로 한정한다. 개인과 각 AI의 보유수량을 구분해 기록하고, 주문 검증 시 해당 AI의 보유수량과 실제 계좌의 매도 가능 수량을 확인한다. 어느 쪽도 초과하는 자동 매도는 제출하지 않는다.
- 수동 매도는 개인 또는 특정 AI를 선택한 상태에서 해당 투자 주체의 보유분 안에서만 가능하다. 개인 화면에서는 개인 보유분만, AI 화면에서는 중지 완료된 해당 AI 보유분만 매도한다. 선택한 투자 주체의 보유수량을 초과하는 주문은 제출하지 않는다. 예를 들어 개인 8주·AI 5주를 보유하면 개인 화면에서는 최대 8주만 매도할 수 있다.
- 실제 체결수량만 선택한 투자 주체의 보유수량에서 차감하고, 현금·손익·거래내역도 해당 주체에 반영한다. 미체결 수량은 보유수량에서 차감하지 않는다. 이후 AI는 자신의 갱신된 보유수량으로 판단한다.
- 같은 종목에 미체결 또는 접수 확인 중인 수동 주문이 있으면 새 자동 주문을 제출하지 않는다. 매수·매도 방향이 같아도 이 제한을 적용한다.
- 수동 주문이 종료되면 최신 보유·주문 상태를 반영한 새 판단을 거쳐 자동 주문 여부를 결정한다. 제한 중 나온 판단을 그대로 실행하지 않는다.
- AI는 수동 주문을 정정하거나 취소하지 않는다.

### 자동매매 중지와 재개

- 각 AI 트레이더에 별도 중지 버튼을 제공한다. 중지 버튼을 누르면 ‘{AI 이름}의 자동매매를 중지할까요? 이 AI의 미체결 자동 주문은 취소됩니다. 보유종목은 그대로 유지됩니다.’를 표시하고 ‘돌아가기’·‘중지 및 주문 취소’ 버튼을 제공한다.
- 사용자가 중지에 동의하면 중지 절차를 시작한다. 돌아가거나 확인창을 닫으면 현재 실행 상태와 주문을 유지한다.
- 사용자가 중지 버튼 또는 수동 매도 전 확인에서 중지에 동의하면 해당 AI의 새로운 판단과 자동 주문 제출을 즉시 중단한다. 이미 제출한 자동 주문의 미체결 잔여수량에 취소를 요청한다.
- 중지 전에 시작한 판단이 완료되어도 그 결과로 새 주문을 제출하지 않는다. 취소 대상은 해당 AI의 자동 주문으로 한정한다.
- 취소 요청 후에도 주문 상태를 조회해 종료 여부를 확인한다. 접수 확인 중인 주문은 접수 여부를 확인한 뒤 미체결 잔여수량을 취소한다. 취소 중 체결된 수량은 실제 체결 결과대로 보유·현금·거래내역에 반영한다.
- 모든 자동 주문의 종료와 최신 보유수량을 확인하면 ‘중지 완료’로 표시한다.
- 취소 실패·미체결 주문·확인되지 않은 주문이 남아 있으면 ‘중지 처리 중’으로 표시한다. 원인과 재확인·취소 재시도 수단을 제공한다.
- 중지 완료 후에만 해당 AI 보유분의 수동 매도와 자동매매 재개를 허용한다. 개인 수동매매와 다른 AI 트레이더의 운영은 해당 AI의 중지로 제한하지 않는다.
- 사용자가 재개하면 최신 시세·보유·미체결 주문·해당 AI의 사용 가능한 현금과 수량을 다시 확인한다. 개인과 모든 AI의 장부 합계를 실제 계좌와 대조한다.
- 최신 상태 확인이 끝나고 장부와 계좌가 일치하면 즉시 새 판단을 실행한다. 필요한 최신 상태를 확인하지 못하거나 장부가 불일치하면 새 자동 주문을 제출하지 않는다.
- 중지 전에 나온 판단을 재사용하거나 중지 중 놓친 정기·조건 판단을 몰아서 실행하지 않는다. 새 판단 이후에는 정기 판단과 조건 판단을 다시 수행한다.
- 노트북이나 Docker 서버가 재시작되면 이전 실행 상태와 관계없이 자동매매를 중지 상태로 시작한다. 기존 주문의 상태는 다시 조회하며, 사용자가 재개해야 새 판단과 자동 주문 제출을 시작한다.

### 후속 검토: Codex 활용

LLM API와 월 구독 Codex를 함께 활용하는 방법을 검토한다.

- 증권사에서 얻지 못하는 정보가 필요하면 앱이 요청을 남기고, 맥북의 Codex가 조사한 결과를 앱에 전달해 판단에 활용하는 흐름을 원한다.
- 연결 방식과 처리 시점은 미정이다. 메시지큐·Kafka 도입은 실제 필요에 따라 검토한다.

### 후속 검토: AI 트레이더 간 피드백과 학습

- AI 트레이더가 각자의 성향·지표·장기/단기 전략으로 종목과 매매 시점을 판단한다.
- 각 전략의 거래와 성과를 구분해 장점·약점을 관찰한다.
- 결과를 회고하고 서로 의견을 주고받아 전략 보완안을 만든다.
- 변경 전후의 성과를 비교해 보완이 실제로 도움이 되었는지 확인한다.
- 필요하면 ML/DL 모델을 별도로 학습·개선해 투자 판단에 활용한다.

전략 간 피드백과 ML/DL 학습은 후속 고도화 방향이다.

### API 확인 후 구체화할 사항

- 비교·평가 시점의 환율과 기준 시각, 과거 주문·거래 시점의 환율을 제공하거나 기록할 수 있는지 확인한 뒤 원화 표시·평가에 사용할 환율의 출처·갱신 주기·지연 여부 확인 방법을 정한다.
- API 지원을 확인한 뒤 해외 주문·정정의 원화 입력값을 실제 USD 주문가격으로 역환산하는 방법·환율 적용 시점·호가단위·반올림 검증과 실제 주문 제출 규칙을 정한다.
- 제품 구현에서 실제 기록 API를 연결할 때 AI 판단 기록 이어보기의 커서 조회·페이지 경계·중복 제거·종료 신호를 구체화한다. 프로토타입은 모의 기록 추가를 시연한다.
- 현재가로 전량 매도하는 가정을 기준으로 API 제공 항목을 확인한 뒤 보유분의 예상 매도 비용에 적용할 수수료·세금 정보의 출처와 산식을 정한다.
- 토스 API 호출 한도를 확인한 뒤 병렬 주문의 최대 동시 제출 수와 제출 속도를 정한다.
- 주기 조회가 필요하면 API 지원과 호출 한도를 확인한 뒤 갱신 주기와 지연 여부 확인 방법을 정한다.
- 주문 기능을 활성화하기 전에 세션·종목별 지정가 주문 지원과 접수 가능 시간·미체결 주문 만료·이월 규칙, 정정·취소 제한을 확인한다.
